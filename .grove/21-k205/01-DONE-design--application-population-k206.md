# application-population-k206

## Goal

Make application population admission, registration eligibility, filtering facts
and resource accounting constructible without an arbitrary native-order sample.
Complete this vertical design slice across contract, source evidence, SDL/examples,
finite acceptance, views and consumer charters. Native qualification remains pending.

## Context

Inherit native-discovery-k205's brief and the settled k204 consent/disclosure
boundaries. Read k203's N4 and the current application contract; do not reopen
consent, source ownership, signing or retained four-action behavior. Graph CLI
startup fails with the active-generation refusal; bounded exact-source/SDK fallback
supplies evidence, not graph coverage. Existing G/N/V are the agreed seams.

## Done when

- Derive count, identifier, call/copy and choice admission from named finite
  populous subjects and the actual source/descriptor/action comparison costs.
  Whole-population overflow cannot publish a source-order-selected prefix.
- Every retained identifier is expanded once, using shared ordered registration
  observations without a per-choice walk multiplier or recursive expansion.
  Keep action-compatible fail-before-match and separate conservative negatives.
- Expose bounded native UI/agent/background facts for client filtering without
  discarding helpers, accessory apps, unknown metadata or required launchers.
- Add populous signed-VM acceptance with >256 distinct useful identifiers,
  independently known choices and helper pressure; absence, overflow, deadline or
  unavailable subject does not pass. Pair independent serviceability controls.
- Reconcile this slice's durable/current artifacts and downstream duties; run
  frozen schema/budget/link/render checks with failing controls and visually
  inspect the served changed views. No build/probe/native/VM/signing experiment.
