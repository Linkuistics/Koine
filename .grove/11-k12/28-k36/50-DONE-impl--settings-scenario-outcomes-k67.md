## Decisions (running log)

- 2026-11-23: Placement. This leaf attempts its acceptance inline and makes no
  further split. k53, k56 and k61 each handed the same setup, title and
  liveness duties forward without new evidence. Every helper that it consumes
  now exists, so the stalled-handoff rule of the Grove decomposition procedure
  applies.
- 2026-11-23: New checked reads. The existing reads lack five facts. Two are
  the front process with its PID and the subroles and sheets of the TextEdit
  windows. The other three are the open menus, the enabled state of a menu row
  and the identity of one PID. `vm_exec_reads.py` gains six reads for them. They are `front-process`, `textedit-windows`,
  `open-menus`, `menu-row-enabled`, `menu-item-selected` and
  `process-identity`. Each parse refuses a missing
  value or an incomplete enumeration, so that evidence is unavailable, never a
  negative.
- 2026-11-23: Open-menu oracle. The read uses the System Events `selected`
  property of each menu bar item. No Apple source states that a menu bar item
  reports its open menu through AXSelected. The oracle is therefore unverified
  natively, and E01 qualifies its availability. A missing value is unavailable.
- 2026-11-23: Liveness seam. The pre-click identity is one `launch-identity`
  read. The liveness read after a zero-window failure runs the same kernel
  script for the recorded PID. Neither read is in the evidence class, because
  python3 can raise the Command Line Tools prompt.
- 2026-11-23: Deferred exhaustion. A clean exhaustion of the count poll latches
  the root, and the latch would refuse the liveness read. The count poll of a
  return therefore returns 1 without its exhaustion receipt. The scenario takes
  the untouched failure reads, then records that receipt before any input.
- 2026-11-23: Scope of each rule. The positive setup runs before the four
  Settings selections over TextEdit. The scenario has seven menu returns: the
  four selections, the requests line, the Accessibility line and the Settings
  selection before Command-Q. The route evidence and the closed-menu read apply
  to these seven. The pre-click identity, the outcome classes and the failure
  observations apply to them and to the app reopen. The title audit applies to
  every front assertion. The two Quit selections keep their existing route,
  because they are not returns.
- 2026-11-23: Final list. A deferred poll prints its final clean list on
  exhaustion. The scenario classifies that exact list. A host file read of the
  root would depend on the backend's directory layout.
- 2026-11-23: Order of a failed return. The liveness read comes first, then the
  observer, the evidence-class window list and the screenshot. The closed-menu
  read follows, because a lost process has no menu to read. The deferred
  exhaustion receipt comes last, because it latches the root.
- 2026-11-23: Outcome classes. Each clean failure of a return records one
  receipt, `scenario-assertion-CLASS`, and the scenario exits 1. The classes
  keep the protocol's distinctions for k57 and k54. An open menu and an
  unavailable liveness read are unresolved, never a recurrence.
- 2026-11-23: Outcome screenshots. A return whose next step is a read or a
  wait keeps its existing screenshot. The first selection and the requests line
  do so. Each other return takes `outcome-RETURN` before its next input.
- 2026-11-23: Red record. The source changed before the controls existed. The
  red record therefore runs the new controls in a copy of commit `c0e0cc02`,
  with only the new tests and the extended simulated backend copied in.
- 2026-11-23: Weak control. The missing-title control passed in the red run,
