# native-observation-ordering-k90 — brief


## Goal

Determine whether the native observation path can attribute closure and reads
to a window lifetime across publication, delayed delivery, loss and reuse.



## Context

Consume native-observation-wire-k89 and its report/discriminator under
docs/verification/native-observation/. Preserve k88's strict read-attribution
boundary. This is a bounded design investigation, not a shipping adapter.

## Done when

- Establish the wire/layout/ownership prerequisites named by k89 before using
  an owned encoder. If that missing link is a separate investigation, decompose
  it before execution; do not invent a layout or adopt an internal stub ABI.
- Freeze both registration orders and run the publication schedules in the
  discriminator, including older closure delayed beyond replies for already
  usable records. Name a native barrier/lifetime premise or its absence and
  dependent refusal; distinguish authentic sender from read attribution.
- Exercise ordinary live closure and Space absence with independent witnesses;
  permanent retirement, duplicate/queued old delivery, registration refusal,
  missing/mismatched provenance, old descriptor reappearance, and controls that
  actually reject wrong-source/old-registration mutations. Label synthetic
  controls and actual descriptor/PID reuse separately.
- Suppressed emission, saturation and failed delivery have independent closure
  witnesses and a detector falsification control. Report detectable versus
  residual silent loss, and read-attribution failure as unagreed for k87.
- Exercise both Preparing exits, unauthenticated discard versus authenticated
  current-registration withdrawal, window/registration/capture scopes and fresh
  registration under the same live capture without reviving old references.
  Inventory observed application/workflow refusals for k87.
- Authenticate every used read/reference/confirmation reply in the prescribed
  fresh-right/request/trailer/live-task order; record correlation/freshness and
  every unsupported native form. Fail the affected operation, never silently
  omit windows. Report precise remaining gaps to k92.

## Notes

All execution is in disposable TestAnyware clones on frozen inputs. Do not
reopen k74 or expand into a general survey. A concrete native failure must be
surfaced before further work assumes feasibility; it does not authorize a
support restriction or read relaxation. k91 separately owns bounded sends and
cleanup; k92 reconciles the whole original k83 charter.

## Decisions (running log)

- k89 leaves the owned registration and notification layouts unresolved. That
  prerequisite and a correctly authenticated live exchange are separate from
  publication/loss semantics and exceed one focused investigation. Decompose
  before sending native requests. First derive a bounded layout/ownership
  dossier from the already frozen bytes, identifying any uninspected branches;
  then validate the owned exchange in a disposable VM before the publication
  and loss/recovery schedules. Preserve every original criterion above. Static
  layouts do not establish native ordering or authorize publication.

## Decomposition and obligation ownership

The original Goal and Done when above remain unchanged. These are bounded
design investigations, not production implementation leaves:

- `native-observation-layout-k93` derives byte-offset tables, reply checks and
  ownership obligations from k89's frozen scans, and names exact uninspected
  links before an encoder is allowed. It supplies static evidence only.
- `native-observation-exchange-k94` closes those wire prerequisites and tests
  one owned add/delivery/remove exchange with fresh authenticated replies,
  source controls, resource accounting and an independent closure witness.
  Unknown layouts or unsafe cleanup prevent execution; they are not guessed.
- `native-observation-publication-k95` owns both registration orders, delayed
  older closure past reads of preparing/already usable records, actual versus
  synthetic reuse, ordinary closure versus Space absence and read attribution.
- `native-observation-loss-recovery-k96` owns suppression/saturation/failed
  delivery and detector falsification; both Preparing exits, discard versus
  withdrawal scopes, duplicate/old registrations, permanent retirement and
  fresh-registration recovery. It reconciles every original k90 criterion and
  forwards precise gaps/refused workflows to k92 and the k87 agreement.

The exchange's minimal safe ownership prerequisite does not discharge k91's
full send-result/ingress-cut/cancellation/drain matrix or k86's maintained
limits. Every child authenticates its own read/reference/confirmation replies.
No parent closes on static tables, synthetic controls or a successful fixture.
No model is used to assume the native lifetime/order facts these leaves test.

k94 decomposed its preflight before sends. k97 supplies pinned request constants
and server-decoder evidence; k98 retains the legitimate client connection and
scalar/policy semantics, and k99 retains receive/cleanup and the witnessed
exchange. k95/k96 must consume that exchange or its concrete conflict, not
infer feasibility from the static request tables. All criteria above remain.
