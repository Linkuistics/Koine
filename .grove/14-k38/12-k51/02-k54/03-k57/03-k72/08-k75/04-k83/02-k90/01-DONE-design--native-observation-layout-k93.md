## Decisions (running log)

- Derive offset tables from the already saved instruction bytes. A literal
  load establishes a location, not the value stored there. Leave request-header
  literals and unresolved field semantics for the precisely bounded k94
  preflight; never infer them from a familiar MIG convention.
- The add/remove/post layouts are a partial specification. Keep the first
  connection port distinct from both the retained destination and notification
  receive ownership; OOL payload limits are separate from inline bounds. The
  next native exchange must resolve these concrete obligations before sending.
  No additional ADR is warranted: no mechanism, public contract or support
  boundary changed. The existing capture/effect/read decisions still apply.
- Spend the one in-session reviewer on re-deriving table, reply, trailer and
  cleanup statements from raw ARM64 bytes. The reviewer found no material
  errors; no second review or automatic review stage is commissioned.
