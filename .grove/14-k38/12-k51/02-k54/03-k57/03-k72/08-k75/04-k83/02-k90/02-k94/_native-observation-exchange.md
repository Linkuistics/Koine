# native-observation-exchange-k94 — brief


## Goal

Establish a safe owned add/delivery/remove exchange through the retained AX
endpoint, or report the concrete wire/authentication conflict before any
publication schedule relies on it.



## Context

Read k93's layout dossier in `docs/verification/native-observation-layout.md`
and k89's original report/discriminator. The dossier contains explicit missing
links; it is not an encoder-ready ABI or permission to use guessed constants.

## Done when

- Close the dossier's bounded preflight: request-header literal bytes, server
  request decoders, scalar/flag/requester semantics, client-port ownership and
  policy, actual notification receive trailer and all touched cleanup paths.
  Pin loaded image/OS identities and freeze each measurement before execution.
  If this prerequisite itself exceeds a focused session, decompose before
  native sends; do not run an internal stub as an adopted adapter.
- Use an owned request to the continuously retained endpoint. Give every reply
  a fresh owned right; record actual request, received kernel audit evidence,
  live held-task comparison, correlation and separate freshness limits.
- Demonstrate one ordinary native registration, witnessed closure delivery
  and removal in a disposable VM; preserve raw bytes, rights/OOL ledger and
  independent target/window witness. Verify wrong-source and old-registration
  controls actually reject, distinguishing synthetic cases from native evidence.
- Validate cleanup sufficient for every path exercised here, including refusal
  and an unexpected reply. Unknown status/ownership prevents the unsafe probe;
  k91 still owns its broader failure/cancellation/send-result matrix.
- Name every unsupported form and refused application/workflow; fail the
  affected operation without omission. Report a precise conflict immediately.
  No genuine lifetime-attributed closure is claimed from sender identity alone.

## Notes

No target instrumentation, helper or extra client consent enters the proposed
product path. Diagnostic comparison/witnesses are separate and labelled. A
successful exchange establishes no publication barrier or complete event stream;
k95/k96 own those discriminators. No k52 implementation or schema change follows.

## Decisions (running log)

- The preflight has independent request-decoder, connection-policy and receive-
  ownership questions before a live exchange can safely run. Decompose before
  native sends. This session closes the bounded request-literal/server-decoder
  investigation on pinned loaded bytes; later children retain connection and
  scalar semantics, authenticated receive cleanup and the witnessed exchange.
  Preserve every original completion criterion. Static decoder agreement does
  not establish a legitimate connection, notification provenance or feasibility.

## Decomposition and obligation ownership

The original Goal and Done when above remain unchanged:

- `native-observation-request-decoding-k97` reads actual header/NDR constants
  and server dispatch/decoders, reconciling the bounded wire specification.
