# callback-causal-fixture-k114 — brief

## Goal

Build and falsify the narrow causal witness instrument before native freshness
measurements depend on it.

## Context

Read the capture assessment's callback witness protocol and guest entry-path
inspection. The witness is currently a design; no callback fixture is supplied
by the loaded-code scan. Use existing TestAnyware/native seam and root Taskfile.

## Done when

- Supply controller, sampler and B/C diagnostic targets with bounded per-process
  streams, local sequence numbers and explicit causal acknowledgment IDs. Keep
  candidate getters out of the independent normal-input recipient witness.
- Freeze the actual native callback mechanism, permission configuration, loop
  gates and case manifest. Distinguish delayed OS delivery from an in-callback
  gate and a worker. No extra client AX consent is authorized.
- Support both bounded pre-held candidates and one acquire/resample attempt,
  separate source pairs, and captured B ownership across a later C switch.
- Build/run analyzer controls first: missing acknowledgment, wrong marker,
  outside-callback sample, cross-process arrival permutation, stale-F/stale-M
  including live PID equality, and release-early ownership. Broken controls must
  fail for the intended reason; record exact exits and raw fixtures.
- Demonstrate ordinary native witness reachability in a disposable clone, while
  distinguishing this instrument check from the full freshness result. Freeze
  all read inputs and compare before/after digests item by item.
- Record reusable commands and instrument limits in the existing assessment.
  Leave full native schedules to k115 and lifetime/policy cases to k112.

## Notes

No production code or public API adoption. If a native mechanism cannot reach
an intended gate without blocking input/disabling a tap, record unreached; do
not silently replace it with a worker and retain the callback label.

## Decisions (running log)

- Separate the executable causal analyzer and its falsification corpus from
  the four-process native fixture. The former can be verified against complete
  and deliberately broken transcripts without GUI execution; the latter must
  establish that real input/callback/ownership events produce those records.
  An accepted synthetic transcript establishes no native reachability or source
  freshness. Preserve all original completion criteria in this node.

## Decomposition

- `callback-causal-analysis-k116` delivers the bounded trace contract, causal
  analyzer, raw synthetic controls, exact exits and reproducible Taskfile checks.
- `callback-native-fixture-k117` delivers the controller, sampler and B/C apps,
  freezes the actual callback/permission/gate mechanism, and demonstrates ordinary
  native reachability with frozen inputs in a disposable clone. It reconciles
  every original criterion above before k115 uses the instrument.

Both are diagnostic design evidence. Full freshness schedules remain k115 and
lifetime/policy cases k112; no production implementation leaf is added.
