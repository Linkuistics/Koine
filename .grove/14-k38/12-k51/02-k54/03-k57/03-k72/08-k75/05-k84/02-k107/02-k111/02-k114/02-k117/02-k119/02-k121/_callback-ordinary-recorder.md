# callback-ordinary-recorder-k121 — brief

## Goal
Produce and verify four-process ordinary native capture and post-callback B
retention across later C input, using the causal analyzer.

## Context
Consume k118's route evidence and k120's extended contract. Audit the producer of
every field; the route-only logs are not capture transcripts.

## Done when
- Replace receipt files with real paired causal messages. Supply controller,
  sampler and independent B/C input witnesses, bounded streams, local sequences,
  actual delivered markers and no target getters.
- Exercise separate public source pairs and both constructions: two pre-held
  candidates and one acquire/resample attempt. Record every native call/status,
  hint/priming call, ownership change and live validation; retain captured B
  across later C input after observed callback return.
- Produce the `returned` observation from a real enclosing/native loop boundary,
  never from inside the callback or a worker that could run before it returns.
  Audit callback depth, run-loop nesting and thread/turn provenance.
- Keep independent sampler/controller policy attribution and no sampler AX
  consent. Use fresh event sources/pairs for every marker.
- Obtain externally observed actual child exits and watchdog/process-tree cleanup
  evidence, including failing exit/timeout controls. LaunchServices launcher
  status and self-recorded intended exits do not suffice.
- Expose build/run through Taskfile; analyzer controls precede native cases.
  Freeze source, binaries, signing/entitlements, dependencies, native images,
  case/permission manifests and all read inputs. Run in a disposable clone,
  preserve exact exits/raw streams and compare all digests item by item.
- Update the assessment/view with ordinary reachability and explicit limits.
  Leave gate/priming schedule closure and parent reconciliation to k122.

## Notes
This is diagnostic design evidence, not product implementation. Extend closed
analyzer vocabulary only with failing controls and a renewed frozen corpus.
Full freshness measurements stay k115, lifetime/policy k112, transfer k108/k109.

## Decisions (running log)

- External process-exit observation is an independently testable prerequisite:
  the route runner measures LaunchServices status and its apps record intent.
  Verify a gated kernel exit observer for independently launched apps, including
  nonzero-exit and timeout/descendant cleanup controls, before capture integration.
  Split that native discriminator from the ordinary capture recorder; preserve
  every original completion criterion. This establishes no capture or freshness.
- k123's six native exit controls match, with external observer waits and frozen
  local/guest inputs. Consume `docs/verification/callback-capture-transfer.md`
  under External exit observer and its contract. The fixed known group does not
  cover unidentified startup failures, unexpected descendants or group escape;
  k124 must integrate and verify full recorder cleanup and provenance.

## Decomposition

- `callback-exit-observer-k123` verifies kernel exit observation and a bounded
  watchdog/known-descendant control for independently launched diagnostic apps.
- `callback-native-capture-k124` completes the four-process native capture path,
  post-return retention, integrated cleanup and every original criterion above.

Both are diagnostic design evidence at the existing isolated native seam. The
first can be falsified without foreground sampling; the second consumes its
limits and integrates the full recorder. k122 still owns gates and reconciliation.
