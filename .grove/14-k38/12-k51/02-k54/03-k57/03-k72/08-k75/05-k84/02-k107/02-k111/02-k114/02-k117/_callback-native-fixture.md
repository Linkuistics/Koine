# callback-native-fixture-k117 — brief


## Goal

Build the four-process causal fixture and establish ordinary native witness
reachability before callback-native-schedules-k115 measures freshness.



## Context

Consume the k116 analyzer contract, executable controls and assessment in
`docs/verification/callback-capture-transfer.md`. Synthetic causal success is
not evidence that a native gate, input marker or callback can reach its order.
The exact guest entry inspection leaves F/M producer freshness unresolved.

## Done when

- Supply controller, sampler and independent B/C input targets with bounded
  streams matching the analyzer. The target records its own PID and real normal
  session input; neither getter nor sampler output supplies its answer.
- Freeze and record the actual native callback, diagnostic permissions and loop
  gates; distinguish OS-delayed entry, a pause within callback and worker work.
  No extra client AX consent. Disabled tap or blocked input means unreached.
- Support both source pairs in separate cases, bounded pre-held candidates and
  one acquire/resample attempt, main-loop/thread/turn observations, and retained
  B across later C input. Preserve per-call status and ownership changes.
- Run analyzer controls before native execution. Demonstrate ordinary native
  reachability in a disposable TestAnyware clone, with exact exits, raw streams,
  input/dependency/signing/permission manifest and itemwise before/after digests.
  Tie acknowledgments to real events and validate the source of each log field.
- Expose build/run through the root Taskfile, update the assessment and view,
  and reconcile every original k114 criterion. All full schedules remain k115;
  actual death/exec/reuse/restoration and policy cases remain k112.

## Notes

No production code or API adoption. Evolve the analyzer contract only with new
failing controls and a renewed frozen run. A synthetic accepted trace cannot
substitute for native reachability, and native getter order cannot prove F/M
freshness while the inspected producer boundaries remain unresolved.

## Decisions (running log)

- Establish the native input/callback route before building a sampler around it.
  A listen-only session event tap with independently delivered AppKit input is
  the proposed diagnostic mechanism; event-field preservation, permission
  attribution and delivery under gates require native evidence. Split a bounded
  route discriminator from the complete causal recorder and sampling integration.
  The discriminator does not emit an accepted capture trace or establish source
  freshness. Every original completion criterion remains binding on this node.
- k118 reaches ordinary independent B input receipt followed by a distinct
  passive callback trigger in two frozen cases, after a missing-receipt control.
  Sampler self-preflights report AX false/listen true/post false. The capture
  assessment retains failed instrument attempts and exact final route evidence.
  Fresh sources/pairs per marker avoid the observed numeric-field reuse defect.
  k119 must replace the receipt-file bridge, measure actual child exits/watchdog
  cleanup and complete the native dependency profile; no capture was performed.

## Decomposition

- `callback-input-route-k118` is an independently executable native discriminator
  for normal-input markers and passive callback delivery with separate permission
  observations. Its route-only records cannot pass as capture evidence.
- `callback-recorder-integration-k119` supplies the complete analyzer-compatible
  recorder, both source/construction modes, gates, ownership and frozen ordinary
  native capture run, then reconciles every original criterion above.

The existing isolated native seam suffices; no new public seam or production
implementation leaf is introduced. Full freshness schedules remain k115.
