# callback-publication-delivery-plan-k223

## Goal
Find the smallest independently useful executable increments from actual files
to the complete publication report, cut and order them as leaves under k203, and
assign every k203 and original ancestor criterion, discriminator and control to
exactly one owner. Name the concrete test-profile hook and production guard.

## Context
The full k205 brief (now this node's brief) and the whole k203…k179 chain.
Design inputs: publication-replay.md, publication-path-controls.md,
publication-capacity.md, transport-lanes.md, transport-evidence.md,
publication-lifecycle.md, publication-files.md and the k204–k222 assessment
sections of callback-capture-transfer.md.

## Done when
- Ordered impl leaves exist under k203 after this node, each a vertical slice
  from real files to reported behaviour, with its assigned IDs in its body.
- The assessment carries a complete criterion/discriminator ownership table.
- The hook, guard and emission/consumption boundaries are named in the replay
  contract and in the owning leaf.
- The numeric profile freeze remains inside k205 and precedes every impl leaf.

## Decisions (running log)

- **Decompose k205.** Its Done when holds two session-sized pieces: the delivery
  plan and a source-audited numeric freeze of every report-profile dimension
  (counting rule instances across analyze.py and all sampler/source modules,
  plus resolving the 2Q(V−1) path-reference bound at V≤10,240). The freeze may
  not leave k205, so it becomes k205's second child (planning kind), which
  pick reaches before any impl leaf. This child does the plan only.
- **Impl leaves are flat siblings under k203, not another nested evidence
  node.** Every predecessor split one helper off and nested "everything else"
  one level deeper; that shape defers delivery. All remaining delivery is now
  cut at once, in dependency order, so each later session starts from a
  working report with named sections rather than a restated charter.
- **Increment boundary is report behaviour.** Each leaf adds whole admitted
  report sections computed from real serialized files, with honest neighbours,
  isolating mutants and fixed-coordinate collector permutations, and keeps the
  legacy analyzer, V1–V26 and every earlier publication check green. Schema or
  helper code with no reported section is never a leaf on its own.
- **Serializer first.** Every later control needs real files and B09/B10/B20
  demand real encoder output; the writer is independently verifiable by
  byte-reproducing the six k217 inputs and remeasuring the capacity census.
- **Admission is not deferred.** The entry leaf builds the admission primitive,
  emergency header, sidecar, guards and test hook; each later leaf charges the
  dimensions its tables consume. Profile-coverage owns the complete
  per-dimension R30/R31 sweep and production-boundary table afterwards.
- **Named boundaries.** Production entry `publication_report(manifest_path,
  rows_path)` binds the frozen `PRODUCTION_REPORT_PROFILE`; test hook
  `evaluate_with_test_profile(manifest_path, rows_path, profile)` takes a
  distinct immutable `TestReportProfile` from an internal test-support module
  the production module never imports; guard `require_production_report` is
  called by the production serializer `emit_publication_report` and by the
  summary/acceptance consumer `summarize_publication_report`, and refuses both
  test-profile reports and `PublicationControlTestResult`. Exact module layout
  stays with the entry leaf, not the names or boundaries.
- **Local rule migration precedes sample claims.** Candidate diagnostics,
  source-selected API names and controller decisions feed interpretation and
  the core; extraction must first prove itemwise legacy equality.
