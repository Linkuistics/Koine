# bookmark-name-resolution-k158

## Goal

Run the one authorized local bookmark diagnostic and obtain Antony's reaction:
can a bookmark recover the original long filename and resolve to a URL that
still reads the exact original file? Produce separate evidence for each stage.

## Context

- The binding charter is docs/verification/focused-zed-route-assessment.md
  #finite-bookmark-diagnostic, authorized by Antony on 2026-10-06. The source
  and charter handoff is long-action-route-k157; returned design is k159.
- Public Foundation NSURL bookmark creation, stored-resource-value extraction
  and resolution options in SDK 27.0; pinned Zed URL-string/path ingress.
- k155's readable/technical evidence and independent original/short-address
  controls; k152's frozen incomplete corpus. Neither may be rewritten or rerun.
- Use using-testanyware for a disposable macOS guest; preserve the prepared image,
  signing and public SDK posture, without host GUI or user/protected files.

## Done when

- Freeze the exact plan, instrument, inputs, observer and per-subject digests
  before collection. Use one disposable guest, one collection, at most two
  builds before it, and a 15-minute clone-through-disposal cap. No repair or
  recollection. Always dispose the guest and retain a teardown receipt.
- Independently component-create the 900-byte control and 1,500-byte ASCII-path
  text fixture, each with an original named basename, same-parent decoy and
  distinct fixed marker. Verify original and bare device/full-inode identities
  and bounded markers before and after each case; failed controls stop incomplete.
  Use no copy/rename/link/alias file, cwd change, protected/remote/user subject.
- Execute exactly the four serialized original-path/bare-ID URL cases at both
  lengths, subject to the charter's stop conditions. Create once per case with
  NSURLBookmarkCreationWithoutImplicitSecurityScope, only NSURLNameKey and
  NSURLPathKey and no relative base. Extract those stored properties; resolve
  once with NSURLBookmarkResolutionWithoutUI,
  NSURLBookmarkResolutionWithoutMounting and
  NSURLBookmarkResolutionWithoutImplicitStartAccessing. Record exact typed and underlying errors,
  missing values, stale flag, URL spelling/base/reference predicate and original
  name/path comparisons. No retries, extra factory patterns, private flags,
  security-scoped creation/access or ineffective PreferFileIDResolution flag.
- For a returned base-free file URL, extract NSURL.path UTF-8 bytes once and
  record them. Issue exactly one whole-path open with O_RDONLY|O_NOFOLLOW|
  O_CLOEXEC, then fstat and at most a 64-byte read. Record extraction failure or
  exact POSIX errno and compare successful device/inode/marker to original and
  decoy. No filePathURL/fileReferenceURL, canonicalization, NSURL/NSFileHandle
  reader, component-walk or short-address fallback for this measured read.
  Component walks supply fixture/control identities only. A non-file or
  base-chained result stops incomplete.
- Enforce at most three caller-owned descriptors, four caller-owned NSURLs,
  one serialized bookmark NSData at most 64 KiB, 8,192-byte stored/logged strings
  and 64-byte markers. Check returned sizes before copying/logging and release
  case values before the next. These caps do not bound opaque native allocation.
  Oversized/unaccounted values or unusable observers stop incomplete.
- Make zero external open/reveal/launch requests and launch no document receiver.
  Unexpected security/consent UI stops without interaction. Grade stored-name
  recovery, resolved URL and actual same-object reading independently. Neither
  creation success nor local reading proves Zed naming or a production route.
- Preserve the plan/instrument/raw corpus and per-input/output digests under
  docs/verification/bookmark-name-resolution/. Write a readable report at
  docs/verification/bookmark-name-resolution-prototype.md, linking separate
  technical evidence as needed. Report actual builds/collections/cases, each
  stage, first failure, caps and disposal. Obtain Antony's reaction before this
  prototype retires; k159 consumes that reaction and the unchanged full route.
