# item-array-submission-k146


## Goal

Run the one authorized finite diagnostic: can either public FSRef item-array
opener deliver the original file spelling to a short recording application at
900, 1,023 and 1,024 bytes, using references from the already measured flat walk?

## Done when

- Build a throwaway ordinary signed helper and short recording app; do not
  implement/change Koine, SDL, grants, conformance, private policy or consent.
  Use one disposable TestAnyware macOS guest and unprotected test-data tree.
  Record OS/build/architecture, SDK/compiler, filesystem/capability bits,
  signatures/entitlements and source/binary/input/output digests. No usage keys,
  protected reads, TCC change, long-copy registration, default-handler change,
  shortened submission spelling or external inquiry.
- Component-create exactly three text-file subjects at 900/1,023/1,024 original
  UTF-8 bytes excluding NUL with valid names and same-parent decoys. Acquire
  transient references in the submitting process by k143's flat named-child
  walk, never by long constructors, URL/reference conversions, handmade bytes
  or an alternate route. Independently verify the short app reference and
  preserve short same-object, decoy and completed absent-name controls.
- Invoke each named opener once per file: six calls per collection, one document
  per call, same explicit short app. The 900-byte calls run first and prove
  listener detection within this corpus. Retain per-call status, timing and
  valid optional outputs separately from recording-app event counts and original
  URL/path byte evidence. An independent reader compares each observed spelling
  against the component-created fixture and decoy. Preserve raw event ordering;
  ambiguous late delivery or status success without exact observed delivery
  establishes no pass. No PSN/launched-reference output is a Koine receipt.
- Permit at most two builds, two collections and one proven instrumentation
  repair; a second collection follows only that repair, for at most twelve
  opener calls total. Retain every attempt and repair reason, never merge runs.
  The aggregate cap is 15 minutes from clone-start request through teardown;
  each native case has an external 30-second watchdog plus at most five seconds
  termination grace. Acquisition stays within 32 levels, eight entries/batch,
  four batches/directory and one live iterator. Process valid final entries on
  errFSNoMoreItems and distinguish container change, error and bound exhaustion.
  Close native resources and stop the guest. Tooling/short-control/bound failure
  returns incomplete; an unexpected dialog stops the diagnostic. No added
  subject, API, guest retry or automatic later experiment.
- Preserve the minimal raw records and a bounded result report, with first
  failed stage and receiver/API distinctions. Reusable mechanics belong in the
  existing Taskfile and are verified before reliance. Present the result for
  Antony's reaction under this kind's skill; long-action-route-k147 consumes
  the committed report and reaction. No production/native action or search pass.

## Notes

1,500-byte reference acquisition, native facts/default binding, long-copy
registration, real default/Zed rendering, Finder selection, grant/cancellation
parity or executable receipt. A negative is bounded to the tested paths.
Keep k144/k141/k135/k130/k128 live; cut no automatic evidence chain or final
review. Production implementation/full acceptance remain planning's work.
