# native-discovery-sources-k200


## Goal

Establish the bounded public/source evidence for v1 native locations and
application/modern System Settings catalogues, and frame the concrete settings
source/posture decision before final API design.

## Context

Consume k196's settled ownership/floor/seams and the parent brief's full
contract obligations. Read docs/verification/native-discovery-sources.md.
The graph CLI refused an active pre-coordination/unverified generation;
bounded source/SDK fallback supplies evidence, without graph coverage claims.

## Done when

- Public location, indexed application, running/registration and settings
  source capabilities/limits are recorded with actual SDK and OS-source
  provenance. Distinguish declarations from native qualification.
- State the settings scripting/Automation versus private-sidebar versus
  explicit category-revision alternatives with a recommendation and concrete
  consumer consequences. No source, consent, signing or useful loss is inferred.
- Preserve useful identities, appropriate explicit actions, G/N/V acceptance
  duties, true blocking ownership and independent action source/binary guards.
  Record exact unresolved contract duties for the parent's final design.
- Serve/check the focused source/decision diagrams and frozen documentation
  checks. Cut focused requirements followed by contract design under k199;
  retire/commit only this child, leaving the full producer live before k7.

## Notes

Source analysis only. No implementation, native probe, backend process, signing
change or VM experiment. The parent's whole-producer review will include this

## Decisions (running log)

- Foundation location values need no contents listing or existence claim.
  Broad indexed application metadata is a candidate source, supplemented by
  running/observed-identifier registration; all-disk completeness and exact
  prompt/hydration behavior remain unproved.
- Modern System Settings' installed dictionary exposes panes/IDs/names/anchors
  and reveal. Its Automation/signing/setup posture is unapproved. Sidebar and
  Sidebar124 have different conditional/catch-all structures; no supported
  complete public catalogue format was established in the examined surfaces.
- Recommend explicitly authorized settings Automation with prompt-free reads
  of an already-running target; a fixed public-destination subset or private
  sidebar adapter would need a different explicit human scope/policy decision.
  Complete the source artifact now; the parent contract waits for that answer.
- Qualify that recommendation: some Apple events are allowed without consent
  according to the SDK. Exact pane-read/reveal events were not preflighted or
  sent. Try the unchanged-posture/no-prompt route first if chosen; the human
  decision permits or refuses explicit setup only if useful discovery needs it.
- Review judgment: this bounded source artifact is consumed by the live
  native-discovery-k199 producer. Its mandatory whole-producer review, cut by
  the actual closing design session, will cover the integrated source/API/
  requirements contract; no in-session or parallel reviewer is materialized.
  Externalized native-settings-source-k201 then native-discovery-k202 as the
  last substantive work, with the parent's full original obligations retained.
