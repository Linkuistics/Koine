# search-resource-feasibility-k111


## Goal
Establish which native error and observation routes can support k109 without
inventing a descriptor guarantee. Deliver source/SDK analysis and a visual
comparison, then hand the unresolved allocation boundary to a fresh design.



## Context

newer than graph generation 2026-09-29T10:36:20Z; NativeWorkspace/dependencies
are not tracked by the graph and docs are excluded. Read exact sources.

## Decisions (running log)

- The CFError-bearing public Launch Services query is an error-observable
  candidate; its SDK contract does not prove a bound on hidden descriptors or
  every internal failure. Do not substitute it mechanically and call k109 done.
- Neither formatted fs_usage nor the available ktrace manual establishes a
  complete normally signed-host descriptor ledger. This is an evidence limit,
  not a claim that tracing that host is impossible. Keep tracing supplementary
  until the actual posture and allocation families are established.
- Decompose the allocation boundary and acceptance construction into k112/k113.
  Prefer a design whose resource argument does not depend on attaching to opaque
  library code; a helper is a candidate, not an accepted process/signing change.
