# native-discovery-k199

## Goal

Return a reviewed native discovery contract for Koine's agreed v1 special
locations and named application/modern System Settings catalogues, with raw
filesystem search entirely client-owned.

## Context

Consume search-tool-permissions-k196's exact human revision and agreed test
expectations, docs/requirements/modaliser-workflows.md and
docs/adr/raw-filesystem-search-belongs-to-clients.md. The support floor is macOS
26+ within the existing Apple Silicon matrix. No general OS metadata-query API,
older-OS/legacy compatibility programme or hidden raw traversal fallback is v1.
Earlier search-tooling-k195/k197/k198 (integration f6e0c27d) and raw/custom-walk
documents are bounded comparison input, not a selected catalogue backend.

This root producer precedes app-and-file-search-k7 and its mixed retained
permission/metadata/resource/review/planning chain. Produce design/source
analysis only; no implementation, backend subprocess/native probe, signing/
consent work or VM experiment here. Surface a public-platform limit once with its concrete
consumer consequence rather than growing another evidence chain.

## Done when

- Establish what OS-known starting locations and named native application/
  modern System Settings categories v1 returns. Verify actual supported public
  sources against source/SDK/primary documentation. Define useful inventory,
  availability/completeness, observation provenance and limits without claiming
  an exhaustive all-disk inventory from partial seeds or silently reducing the
  intended “all apps”/settings choices to arbitrary witnesses.
- Define the native GraphQL contract, input/output validation, authorization/
  revocation and publication behavior, honest healthy empty/blocked/unavailable/
  incomplete/unknown outcomes and diagnostics. Clients own raw traversal, their
  permissions, filtering/ranking/order/budgets and presentation. A location
  value neither lists contents nor grants filesystem access or OS consent.
- Preserve useful per-installation application identity, identifier/registration
  facts, distinct same-identifier copies and appropriate explicit selected
  actions. Define usable modern settings destinations and any necessary action
  additions with their complete authority; do not assume an existing action
  accepts a new destination shape. Existing launch/open/reveal resolution,
  control requirements and v1 handoff limits remain independent.
- Qualify each actual native source/target under prompt-free/no-hydration reads.
  Bounded existing lookup-only identification is allowed only for its individual
  targets, with its accepted contact/blocking/alias/replacement limits and real
  acceptance obligations. Earlier fixed-find permission was for the removed
  raw feature: it selects no catalogue child, custom walker/helper, global OFF
  pin, consent/setup, signing/entitlement/usage-key, descriptor-limit or coverage
  change. If an actual source needs a new decision, present the precise gap and
  a concrete alternative rather than inferring approval.
- Define bounded native work/copies, blocking/late-return ownership, cancellation/
  revocation/provider-stop and independent serviceability. Preserve source AND
  actual binary action authority guards with meaningful failing cross-boundary
  controls. Observed native facts/health and opaque resource peaks retain their
  stated limits, without accepting known incorrect or systematically missing
  useful choices.
- Record finite acceptance through the agreed three seams: GraphQL locations/
  catalogues and authorization/revocation/outcomes; actual provider/host binaries
  for metadata/loading/compatibility/action authority; signed macOS 26+ VMs for
  real starting locations, twelve configured launchers plus Safari/Finder,
  modern settings destinations and appropriate explicit selections, with
  independent dialog/hydration controls. Unavailable subjects remain pending.
  Define exact new provider/schema/profile/update/refusal subjects while
  independently retaining action-only 1.0.0/1.0.1 evidence; do not relabel old
  captures as native catalogue acceptance.
- Replace the retained raw proposal in workspace-search and reconcile SDL/
  examples, client guide, Machine/workflow trace, ADR set, glossary, conformance/
  verification applicability and architecture sources/manifest/exports.
  Classify previous raw mechanisms as comparison, not current product promises.
- Reconcile every mixed live charter before its consumer executes: k7, k19,
  k126/k191/k193, k127, k123, k120, k30 and k93. Keep required native metadata,
  permission, binary/action and serviceability work; raw home/order/work
  omissions are client-owned. Leave mandatory whole-producer reviews correctly
  placed and Creator naming to the sessions that actually finish their producers.
  No ambiguous leaf is pruned or credited as passed. Any obsolete-only work
  needs explicit human pruning under Grove, not an inferred terminal mark.
- Run frozen checks appropriate to changed SDL/examples, links and rendered
  views. These checks supply no native/binary/VM pass. Cut mandatory review-design
  with **Reviews:** native-discovery-k199 before app-and-file-search-k7;
  its earned integration also precedes k7. Record the review judgment and finish
  with a concrete reconciled handoff.
