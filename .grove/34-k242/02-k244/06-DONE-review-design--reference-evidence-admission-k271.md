**R2 — One-attempt consumption is recorded only by a separately deletable entry, so
ordinary cleanup re-admits a second pass (high).**
Coordinates: C:327–336, protocol steps C:348–366, limits C:371–375; admission-repair
control rows C:923–925. The receipt grants one attempt but is never consumed; consumption
exists only as the attempt directory created in step 3. Deleting or moving that entry out
of the subject, while the receipt, subject directory and ancestors keep their identities,
passes step 1 (valid receipt, unchanged subject), step 2 (lock free) and step 3 (exclusive
create succeeds): a second target attempt is admitted with no forged artifact. Restoring the
whole subject from backup is detected (new inodes), so the protocol catches the elaborate
case and misses the simple one. The contract files this under "indistinguishable rollback
and unobserved delete/restore remain adversarial limits", but removing a failed attempt's
large evidence is a cleanup, not tampering, and is exactly the "silent repeat" the canonical
permission forbids. A cooperative design that consumes the authority itself (for example
moving the receipt into the attempt under the held lock, so deleting the attempt leaves no
admissible receipt) closes it without a stronger store, so this is a design gap rather than
an inherent limit. No control row covers attempt-entry deletion/move with the receipt intact.
Contract basis: canonical permission ("permits no silent repeat"); k268 F1 ("moved/deleted/
unreadable evidence"); C:364 ("Recovery of that possibly unused pass needs explicit new authority").

**R3 — The no-contact boundary omits target contact proxied over IPC, which neither the
gate nor the syscall collector can see (high).**
Coordinates: C:72, C:435–471, C:482–491, C:500–506 ("refuses before real mdfind exec or
installed-root syscalls"), C:929–931; diagrams.json native-reference-proof caption and
discussion summary ("an external DTrace candidate must detect direct syscall bypass").
The forbidden source contact is defined as an exec of /usr/bin/mdfind and the collector as
syscall/process events of the scratch process tree. Spotlight queries need neither: an
in-process Metadata framework query (MDQuery/NSMetadataQuery) reaches the index through
Mach/XPC messages to a system daemon, with no exec, no filesystem syscall on an installed
root and no gate intent, because the gate only sees operations an adapter chooses to
present. Daemon-proxied file access (LaunchServices, file coordination, bundle or URL
resource APIs) has the same shape. A miswired or regressed adapter could therefore query
the real index during rehearsal and leave both a clean gate log and a clean external trace,
which is the bypass F4/F5 asked the design to close; the rehearsal's "without mdfind
contact" claim is unverifiable for the source side. The contract never names IPC, Mach,
XPC or the Metadata framework. Contract basis: k268 F4/F5 ("real pipe/syscall contact,
with a deliberate direct-bypass control"; "without mdfind or installed-root contact");
C:461 limits only prompt/hydration safety, not proxied contact.

**R6 — Observer coverage is defined by the producer's reachable primitives rather than an

Coordinates: C:445–453 ("every actual lookup/listing/open/read primitive reachable in the

**R7 — Reservation durability is claimed to be qualifiable in pure scratch scope, which cannot
observe OS-crash persistence (medium).**
Coordinates: C:355–363, C:368–370 ("Actual scratch qualification must establish locking,
exclusive-create and persistence ... with two processes, crash points"), C:925. Process death
leaves the page cache intact, so killing the coordinator at crash points shows ordering and
retention, not durability; power loss or kernel panic needs native/VM work this design forbids.
The consequence is the one F1 exists to prevent: a reservation acknowledged but not actually
durable, followed by target spawn and an OS crash, leaves no entry after reboot and the next
caller is admitted to a second pass. The design should state persistence across OS crash as a
documented-API assumption (or an explicit limit for Antony) and forbid crediting kill tests as
durability proof; as written, a construction session can mark "persistence qualified" from
evidence that cannot show it. Contract basis: k268 F1 ("durable start before contact"; "State
the enforceable boundary"); C:371 ("Unsupported or unknown durability/identity refuses").

**R9 — The inherited literal /System rule admits the whole data volume, including consent-
protected locations, without that breadth reaching Antony (medium).**
Coordinates: C:549–553, specimen rows C:559–560, C:566–577; canonical permission
(application-population-metadata-shape.md:219–221, no "new consent ... posture"); the ADR's
