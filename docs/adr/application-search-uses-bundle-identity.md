# Application search uses bundle identity

Search merges direct, checked-link and OS-reported routes by established native
bundle directory identity, retaining its first finalized resolved target spelling
and observed source membership. Distinct copies sharing a bundle identifier stay
separate. The [match contract](../specs/workspace-search.md#matching-and-returned-locations)
owns observation limits; files remain command-reported locations.

One observed installation becomes one chooser choice without an unbounded history
of discarded routes. Link aliases supply no extra application comparison name and
cannot substitute for an uninspectable target. That selection contract is surprising
and costly to change after clients rely on it. It costs bounded native inspection
under the separately approved search permission policy; no spelling/identity pin
or movement guarantee follows. Matching uses Foundation; ranking/MRU is client-owned.

Path-only dedup duplicates link/direct installations; identifier-only dedup merges
real copies. Keep either as unknown/omitted when native identity cannot be established
rather than inventing a merge. Revisit for a concrete alias-launch requirement or
measured native limitations that defeat useful search. Actions revalidate both
selected identifier and installation path under their existing contracts.
