# Native application facts are reported observations

Native catalogues publish checked service observations rather than proof of
the platform's internal health. Registration absence requires a checked present
installation and a supported negative observation; a nil identifier or an
empty, malformed, incomplete, blocked or conflicting service result alone
establishes no negative fact. The
[native catalogue design](../specs/workspace-search.md#application-sources-and-native-facts) defines exact
positive, negative and unknown branches for error-bearing registration and
preferred-location contradiction checks; actual runtime qualification remains pending.
Application choices also carry explicit nullable agent/background declarations
and associated running-policy observations for client filtering; unknown flags
are not false. The [population contract](../specs/workspace-search.md#application-population-admission)
shares bounded observations and invalidates publication on global overflow, so
native order cannot silently decide which useful copies survive. Its certificates
and populous acceptance remain design/qualification obligations, not health proof.

The fixed indexed item projection can supply reported type/name/identifier for
long choices when whole-path Bundle metadata is unsupported. Current descriptor
identity does not bind stale index values to current bundle contents. Public
metadataSource distinguishes that observation; INDEXED_ITEM retains UNKNOWN
installation state and null unsupported bundle flags. The
[long source subject](../verification/native-discovery-acceptance.md#long-application-source-subject)
requires real query tuples and independent fixture facts, with known wrong values
failing qualification. A descriptor-relative plist reader changes the admitted
mechanics; suffix/client-path substitution supplies no native evidence. Actual
missing long tuples remain an unmet useful obligation, not an accepted reduction.

An undetected failure or stale native state can make a fact incorrect or omit a
choice. Known incorrect witnesses and systematically unknown metadata for the
configured launchers still fail acceptance. Useful discovery, per-copy identity,
existing explicit actions and their authority remain requirements under the
[ownership decision](raw-filesystem-search-belongs-to-clients.md). Native sources
cannot silently substitute a partial seed list for an exhaustive all-disk claim.

The native contract retains checked negatives without claiming opaque platform
health. Its indexed breadth and witness supplements never define an exhaustive
inventory. Historical raw traversal/seed accounts are comparison input. Its
[source/SDK analysis](../verification/search-native-resources.md#call-health-is-separate-from-descriptor-visibility)
supplies no token proving every internal acquisition healthy. Suffixes or private
registration scraping would not preserve required native launch semantics.
Reconsider stronger fact claims only if a supported health-bearing native route
exists or measured incorrect facts defeat useful discovery.

This decision provides no opaque-allocation bound or runtime pass. Actual
provider/host binaries and finite signed macOS 26+ subjects must qualify the
selected sources, independent serviceability and dialog/hydration controls.
Unavailable subjects remain pending; action-only captures are not native
catalogue acceptance.
