## Retained entry and domain channel

The commissioned checker owns launch policy and the live register lock, as specified in
the [approval protocol](application-reference-evidence.md#invocation-channel-and-verifier-self-qualification).
Its public packaging request accepts only one fresh export destination. Its independently
commissioned launcher has fixed LIVE and private qualification SCRATCH launch roles under
the [independent release supervisor](application-reference-evidence.md#independent-live-release-and-role-selection);
there is no public mode, authority, query, runtime, root or adapter override. Rehearsal
enters the actual checker's export-request parser and packaging dispatcher with the same
export-only argv as LIVE, never by calling its shared launch routine directly. The
private pure seam supplies a fresh out-of-band parent-launch challenge fixing SCRATCH.
Only the independent release owner's still-live supervisor, after independent acceptance,
audit and distinct k244 close, explicitly opens one k245 invocation and originates LIVE's
parent endpoint. Pure/task callers receive no LIVE entry capability, even after a validated
receipt or ELIGIBLE release exists. A saved release is P evidence, not a bearer or role
selector. Both roles require earlier
independent commissioning and actual parent/image/endpoint correspondence, not an
environment selector. A missing parent challenge refuses without preflight or fallback.
The checker compares request/export/domain/closure bindings and creates a different fresh
channel for the following exact retained chain; no parent endpoint is reused as a verdict:

| Boundary | Proposed fixed entry and invariant |
| --- | --- |
| Task runner | Absolute retained task executable; argv `--taskfile <retained>/Taskfile.yml --dir <retained> reference-evidence:package EXPORT=<destination>`. Every item is a separate argv element. The independently checked request binds these exact bytes, cwd and image. |
| Packaging Taskfile | Standalone retained `Taskfile.yml`, schema version 3; one package recipe, no dependencies, includes, dotenv, remote files, dynamic shell variables, build/install/resolution or implicit checkout entry. Its full bytes are measured. |
| Launch script | Fixed retained script and interpreter; exactly one quoted destination argument, no eval, shell expansion of destination, PATH resolution, startup files or adapter choice. Task's `shellQuote` must round-trip the accepted destination. A non-round-tripping spelling refuses before reservation. |
| Acquisition CLI | Same retained executable and `package --export <destination>` parser in both domains. Unknown/duplicate/missing arguments, arbitrary source/scope/file/language parameters and extra task arguments refuse. It independently compares parsed export bytes with the launch request. |
| Domain enabling point | Independent supervisor selects LIVE before Task; pure launcher can select only SCRATCH. Mandatory unnamed channel at inherited fd 3 follows the exact task/script chain by explicit descriptor actions and carries the fresh checker challenge, original role appointment and (LIVE only) current release/close basis. No file, environment secret or reusable success token selects a role. |
| Composition | After channel/identity validation, one composition routine selects LIVE fixed adapters or the closed SCRATCH operation mapping. Parser, fixed constants, preflight decisions, coordinator, native decoder and publication/derivation logic remain the retained candidate. |

These names specify future construction, not currently runnable commands. The root
Taskfile currently supplies presentation and legacy lossy-capture recipes; it is not this
packaging Taskfile. A project-root convenience wrapper may request the checker but is not
an alternate admission entry. If used, its entire actual task/script/configuration reads
join qualification and live equality checks. The selected retained direct route does not
inherit a root-wrapper proof. Construction also supplies a distinct pure qualification task
that asks the independent launcher to run this package chain in SCRATCH; ordinary tests
have no LIVE dependency. No packaging scaffolding is added in this design session.

**No missing-channel default exists.** Before preflight, the CLI must receive one complete
challenge from the still-live commissioned checker, verify its independently observed
process/image and exclusive endpoint ownership, and bind export, invocation nonce, expected
domain, original role appointment, LIVE release/close basis where applicable, accepted
revision, exact task/script/CLI/read closure and allowed initial state.
Use k275's length framing, sequence, EOF and true-return rules; the reverse endpoint stays
available for acknowledgements. Task/script intermediaries may pass this endpoint only
along the accepted chain and cannot write a verdict. Accidental fd closure, inheritance
to another child, replacement, unexpected writer, missing correspondence or supervisor
death refuses. fd 3 is an explicit internal interface; its preservation by the actual
Task runner and interpreter is a required unestablished C3/C6/C8 qualification cell.

The independently accepted launch record fixes SCRATCH or LIVE **before** starting Task.
Neither task arguments, environment nor coordinator messages can change it. A LIVE launch
rejects every scratch map, fixture authority, scratch revision/result, selector variable or
extra inherited capability. A SCRATCH launch rejects LIVE verdicts/intents and never opens
the fixed live permit subject. The checker has separate domain validation paths, both
using the same request/parser logic; SCRATCH controls submit the other domain's
valid-looking messages for refusal without selecting LIVE. Receipt publication and final
validation leave qualification disarmed. Provisioning/corrections disarm before changed
inputs are used; last-edit requalification, independent acceptance/audit, distinct close
and independent release must settle before a new supervised k245 invocation. Missing,
partial/stale release or supervisor loss refuses before intent and freezes source release.
Possession of a socket number is no authentication. Required known endpoint/process/image/descriptor correspondence consumes named B3/B6/B8
Q/P controls; complete opaque pre-start rights/maps/proxy closure stays accepted unknown; deliberate same-UID trust-root forgery retains
the selected cooperative limit. This design promises no OS sandbox by naming a channel.

The outer commissioned checker and independent boundary must be ready before the first
Task/interpreter/loader operation. The coordinator's gate begins too late to cover startup
constructors. If a task edge bypasses the script, invokes mdfind, loads a substituted image
or drops the channel, required independent retained-edge/parser/domain and named scratch-operation controls
must detect/refuse that deliberate counterexample at its intended boundary. They cannot
prove every unobserved native/startup/proxy bypass absent. An invalid channel cannot be tested by actually attempting LIVE contact.
Until those required named controls/identities qualify, this entry has no Q credit.
Their scoped success supplies no complete startup/pre-effect contact certificate.

Keeping the shared project Taskfile would simplify invocation but bind unrelated changes
and its dynamic dependency environment. A separate internal coordinator entry would miss
Task/script/parser preflight. The selected standalone chain localizes those reads and
rehearses the actual packaging entry, at the cost of explicit launch/channel commissioning.
Revisit it if the retained runner cannot preserve the channel or its required known startup/entry/image
claims cannot qualify; retain the unavailable boundary rather than credit a shorter path.

## Operation and credit map

Evidence credit and execution stage are separate dimensions. **E** credits an actually
performed operation, with its retained image, raw operands/results and independently
checked claim. **M** credits only an independently checked logical-to-scratch mapping;
it does not credit the native destination or its behavior. **U** records a claim that
has no qualifying evidence. None is a blanket permission or an aggregate pass.

Every required claim additionally has exactly one stage fixed in the independently
accepted inventory **before** measurement:

| Stage | Requirement and blocker |
| --- | --- |
| Q — earlier qualification | Required tool mechanics, independent expectations, identities, entry/domain/refusal controls and accepted anchors must pass before instrument qualification/release. A failed, missing or stale required Q claim blocks; M cannot replace required actual-call E evidence. |
| P — fresh pre-consumption validation | Actual invocation facts are obtained and checked using already qualified mechanics. Missing, changed, uncertain or refused P facts stop before `consume.intent`, permit rename, original start or target contact. An earlier sample never supplies a fresh P fact. |
| A — authorized-attempt outcome | Behavior that can first be observed only in the selected initial/closure acquisition remains unobserved until that attempt. It blocks successful evidence publication when missing/failed, rather than blocking the attempt on its own prior success. All Q/P/release obligations must already hold. |

Applicability is claim-specific: both domains require actual UID/channel/parser/runtime
mechanics; only LIVE requires the fixed receipt's current state; only target acquisition
has actual installed-query/root outcomes. A scratch source pipe has no installed app
ancestry claim. These are semantic reasons fixed independently, not post-run excuses.
One operation can have separate Q mechanics, P operands and A results; each gets its own
coordinate. Accepted contact unknowns retain their distinct limitation coordinates under
the canonical bounded-contact amendment; they are neither passed E nor inapplicable.

### Non-consuming qualification routes

Q uses the existing independently authored pure-byte/value/association and actual
unprivileged scratch seams. The native-operation programme calls only O05–O07's exact
UID/build/random/channel APIs and O21's parser on constructed bytes, with separately

not installed source/index/application contents. Earlier bootstrap/adjudication exercises

no valid LIVE launch is a qualification positive. Independent narrow observations record
actual API operands/results/images; mock results or source pins cannot supply E credit.
The commissioned launch identity and separately accepted current API/build correspondence
provide external comparisons; unknown correspondence keeps Q/P unavailable. No collector
probe, real service request or new privilege is introduced by this specification.

O09/O11/O12's **actual** fixed-namespace facts come from the already selected separately
owned one-time initializer and independent validator, after their scratch mechanics
qualify. They inspect only independently reviewed exact authority/ancestor operations,
publish staged/final bindings and required real synchronization acknowledgements. They
never select packaging LIVE or touch target applications/indexes. Final validation is a
P input, not qualification of target behavior or LIVE activation. Provisioning cannot
be repeated to calibrate or recover; later changes require independently accepted
correction/affected requalification without restoring consumed authority.

O10's actual requested export is checked once in that explicit packaging invocation's
pre-intent preflight. Its primitive mechanics must already have Q evidence. A fresh
destination's identity/capacity/acknowledgements are P facts, not a reason for an earlier
trial LIVE invocation. Unreviewed export/authority ancestors, protected/unsettled risk,
unavailable required identities or unknown synchronization semantics refuse. If a
required fact cannot be obtained by these selected routes, name the exact operation,
missing evidence and concrete scope/authority trade-off for Antony before the consumer;
do not invent a live-validation mode, target permit or unstated inapplicability.

The alternative of a LIVE invocation guaranteed to stop before intent is rejected for
qualification: it would introduce another role-selection/entry promise and could consume
authority if miswired. SCRATCH actual-call tests plus separate qualified provisioning
and fresh P checks answer the required facts without that role. K285's separate independent
release and chartered acceptance order governs the repaired k282 conjunction; no operation-credit result,
receipt publication or final validation may arm a qualification invocation.

### First-attempt outcomes and required counterexamples

Only O15–O22's actual selected target source/root/file/parse/closure outcomes, plus the
post-intent authority/output transitions O13–O14/O23–O24, first occur in A. They are not
required as earlier successful target samples. Required Q mechanics/independent type
expectations, exact retained images, entry/domain/refusal controls and every P authority/
build/UID/channel/export/input fact remain prerequisites. An installed operation not in
the reviewed fixed plan is forbidden, not another A cell. Target results can qualify
the package's stated evidence only; they cannot repair a tool defect, calibrate wiring,
prove no-contact or replenish the one attempt.

An unsuccessful A call retains raw response/extent/error, phase, object/association and
unperformed work. The first irreversible intent/rename boundary fixes consumption even
when no source call succeeds. Required refused copies carry the canonical explicitly
accepted failed/incomplete boundary through k245/k246/k247; they supply no complete finite
subject, private eligibility or useful loss. Two observations are not an atomic snapshot;
opaque source/index/proxy, hidden-ancestry, TCC and native-race limits remain explicit.

The independent required inventory pairs: complete Q plus valid P with first-source
failure (consumed/incomplete, no retry); missing Q/native image/control with otherwise
valid P (pre-intent refusal); stale/mismatched UID/build/ancestor/receipt/channel/export
with valid Q (pre-intent refusal); mapped sysctl/UID/parser success without actual required
E evidence (Q refusal); actual scratch E with target behavior still U (no target-success
prerequisite); first-root/race/closure failure (exact incomplete evidence); and an
undeclared native call relabelled A or an accepted contact unknown relabelled failed Q
(inventory/value refusal at the intended coordinate). Positives run on constructed
scratch subjects and independent known answers; they cannot consume the target pass.

Acceptance is stage-specific, with the inventory checking all sets in both directions.
At Q close, no required Q claim is failed/unavailable/stale; P facts are expressly pending,
not fake passes. Before intent all required P facts and the separate independent release
must hold; A observations are expressly unperformed. Complete evidence publication needs
all required A outcomes/comparisons or the truthful failed/incomplete disposition. Only
the specifically selected bounded-contact classes may remain unknown without blocking
Q/P. Their full C1–C8/U1–U6 claim reconciliation is separate required work; the canonical
amendment cannot waive unrelated U operations, identities, native expectations or controls.

Each SCRATCH mapping binds operation kind, raw logical operands/flags, role and generation
to exact held scratch descriptors or emitter image/argv; both directions are checked.
Mappings cannot be prefix substitution, reconstructed paths, arbitrary service names or
"all reads under this directory". Unknown/extra requests, absent mappings or mismatched
role/generation refuse before issuing them. Intended logical paths and independently
observed actual scratch calls have different provenance records. Mutable specimen bytes
live only in the named isolated scratch subject; no fixture descriptor resolves live scope.
Native sysctl/UID/image operations require their own permitted operation/object records,
