# Application metadata finite design subject

[Freeze the finite subject](../design/architecture/index.html#diagram-native-metadata-subject)
shows the evidence boundary and next decision. Graphs start at the dark **Start
here** node; numbered edges express work order. This document and the
[per-item JSON](../design/application-metadata-subject.json) establish a complete
bounded file census and disk-only construction. They select no replacement
reader format, precedence, file bound, owned-budget rule or useful-category loss.
Application-localized-metadata-k215's consumption hold and mandatory whole-producer
review remain binding. Every native G/N/V verdict remains **pending**.

## Measured baseline and scope

The captured development Mac is macOS 26.6.2 (25G83). The fixed indexed predicate
returned 789 path slots. Contents were measured only for checked `.app` directories
at observed spellings under `/System`, `/Applications` and `/Library`: 640 spellings,
including all fourteen required launcher/system witnesses, the Unarchiver and
indexed nested helpers. The 290 `/System` directory spellings match the earlier
bounded counterexample. All other 149 query paths are recorded with their exclusion
reason, including out-of-scope paths and non-directory/non-`.app` results. They are
not silently treated as bundles or omitted from the raw query evidence.

Safari is an observed root symlink. The manifest preserves its indexed spelling
and separately checked resolved directory and device/inode; it does not call the
symlink itself a directory. Alias resolution at the root is distinct from refused
fixed-file/locale descendant symlinks. The construction uses directory-relative
access for long fixtures. This evidence instrument is not Koine's reader or
LocationWalk, and its access is not a reader safety, permission or hydration pass.

This is **not an exhaustive supported-VM baseline**, nor this development host's
complete admitted native catalogue. The excluded paths can consume native source
and population gates before content inspection. No normally launched signed VM,
actual NSMetadataQuery/AppKit/CF batches or independent native observer was run.
The future supported matrix must capture its own full baseline and all source
slots, including out-of-scope, malformed and repeated candidates. No host category
has been removed from the product contract to make this bounded evidence fit.

## Independent file and locale census

For every measured directory, record layout probes, selected information/resource
bases, direct raw entries, every checked direct `.lproj` directory and rejected
locale entry. Independently census `Info-macos.plist` and `Info.plist`, plus
`InfoPlist-macos.strings`, `InfoPlist.strings`, `InfoPlist-macos.loctable` and
`InfoPlist.loctable` at the global base and every direct locale. This is an
**evidence superset**, not approval to read all language files or adopt all four
name families in production. The future closed production plan must select its
exact families, locale grammar and precedence with Antony.

The JSON retains present/refused file states, exact regular-file identities,
bytes and SHA-256, dictionary dimensions and exact loctable dictionary keys.
Absent fixed files are represented by the complete census-family rule and
per-item probe/absence counts. Direct `.lproj` inventory and loctable keys are
separate observations; neither inventory substitutes for the other. English and
German name values are retained as witnesses; maximum name length is measured
across all table dictionaries and every fixed locale name file. Python plist
decoding, with plutil on bytes already read where necessary, is evidence decoding;
it is not qualification of the proposed CF parser, native peaks or fallback.

FindMy's plain information name is `FindMy`; its loctable supplies `Find My` in
English and `Wo ist?` in German. VoiceMemos similarly differs from `Voice Memos`
and `Sprachmemos`. Those values are checked against independent literal witnesses.
A name-file set omitting loctable fails the evidence coverage control even when
all its `.strings` probes are absent. These observations establish the missing
format; they do not establish private Bundle precedence.

## Controlled P1024 and L1500 construction

The disk-only controlled additions are 1,010 distinct useful identifiers, 256
distinct agent/background/helper identifiers including one nested helper, and
128 actual alias spellings. All fourteen required useful identities are already
present in the measured baseline, so the useful witness set totals 1,024 without
double-counting them as extra fixture copies. All 640 baseline spellings remain.

L1500 adds seven exact absolute-root lengths 977, 978, 1,003, 1,004, 1,023, 1,024
and 1,500 bytes, plus two distinct short copies sharing the last two identifiers.
The fixed information bytes and en/de localized names differ from plain names;
all direct locales, including Base, are retained. Long contents are actually
constructed/read through held directories. Whole-path construction initially
failed at the 978 localized descendant, and a regression control now covers
contents beyond the pathname limit. No disk construction supplies a native tuple.

The combined stress worksheet has **2,043 distinct spellings/episodes**: 640
baseline + 1,275 controlled directories + 128 aliases. The aliases each incur
another input/inventory episode in the worksheet. Exact raw source-slot repeats
are separately declared in `controlledSourceBatches`; this counterpart has 7,862
URL slots, 128 running slots and 1,871 distinct observed identifiers (1,873 if
reserving two additional system-ID groups). These arrays are explicit controlled
assumptions, not captures of this Mac's native batches, indexing or running apps.
Repeated source slots are not additional file reads for an identical spelling;
distinct aliases in the episode worksheet are. No deduplication refunds charged
input for an episode actually performed.

These are **metadata-only construction fixtures**. Executables, signing, installation
in an indexed VM location, registration, actual native type/current identity,
source provenance, running policies, useful GUI behavior and all serviceability/
dialog/hydration observers remain pending. Native V11/P1024 and V13/L1500 are
independent obligations; combining their disk evidence here passes neither.

The 129-byte name occurs in the full census; it also prevents claiming the old
128-byte name dimension covers every observed candidate. The selected production
language plan is not yet defined, so this is not a final-value overflow verdict.
The direct inventory count alone omits loctable-only key work: the combined census
also has 10,024 locale-keyed dictionaries in loctables. A replacement must account
for their inspection and any owned projection, not insert them into a free term.

The following calculations deliberately reuse the **old full-envelope** 6,816,128
record/payload/scratch reserve and its fixed 128-byte per-locale reservation. They
are conditional counterexamples, not measured allocations, lower bounds on every
possible implementation, selected read plans or replacement certificates:

| Substitution into old reservations | Gross bytes |
| --- | ---: |
| Combined information input + every direct locale | 11,716,027 |
| Additionally every global name file | 14,376,036 |
| Instead every fixed-family census input | 16,543,522 |

Even the information-only substitution exceeds 8,388,608. Reading every locale
file is unnecessary and unapproved; the last row provides an explicit census
comparison, not a recommendation to perform 83,730 probes. It cannot certify a
16 MiB replacement: loctable key work, actual selected-plan storage, final-name
dimensions, long-path transcodes and any changed record/call recipe still need
derivation. A host policy increase is not selected.

Lifetime storage and cumulative charges are different. Two buffers capable of
the measured maximum file would simultaneously reserve 206,394 bytes, while the
information-plus-global census contains 5,271,140 bytes of episode input, before
selected locale files. Reusing those buffers releases lifetime ownership; under
the existing rule it **does not refund cumulative per-read input/copy charges**.
The maximum file suggests testing an explicit 131,072-byte bound, but that bound
has not been adopted and is no universal file-size promise. Any change from
gross input charging to a lifetime/throughput split needs its own explicit rule,
limits, overflow outcome and human selection. Native parsing/object peaks remain
unproved whichever owned accounting is selected.

## Next coupled decision

Application-metadata-budget-k217 must first seek a concrete loctable-capable
construction within the existing gross, call and core response gates. That means
an enumerated selected file/locale plan and owned representations, including
loctable keys, repeated inputs and final transcodes; a smaller scratch peak alone
does not establish a gross fit. If that construction fails, present a fully
derived larger application-owned envelope and its actual relationship to host
policy, preserving the independent core response limit and action/Settings
contracts. An explicit new accounting rule is a separate alternative, never a
silent reuse refund. Category exclusion requires Antony's selection and is not
the recommendation. No alternative is adopted by this evidence.

The following design child must resolve oversize-file individual versus population
outcomes, exact fixed families and all supported layouts, locale-key grammar/
precedence/absence/malformed/denied branches, every explicit call and lifetime,
gross and wire certificates, then reconcile the complete artifact family and live
charters. It cuts mandatory whole-producer review-design of k215 before k7.

## Reproduction and controls

Run `task design:application-metadata-subject` to construct only `.build` fixtures
and capture the bounded installed-file census. It checks each file during read,
then repeats the full baseline/fixture inventories and exact query path slots,
comparing every item. The instrument, tests, Taskfile, input certificates, Python
executable, plutil and mdfind are hashed before and after. A changed subject fails
the capture rather than producing a plausible smaller measurement.

Run `task design:application-metadata-subject-check` for saved-JSON validation and
the instrument's controlled regressions. It reads no installed target. Original
64 KiB information/loctable gates, 1,000,000 input, 4,096 locale dimensions and the
substituted 8 MiB gross certificate deliberately fail; removing loctable fails
the useful-name coverage control. Regression cases exercise a non-directory query
item, distinct direct/table inventories, locale symlink refusal, repeated input,
omitted loctable, long descendants, malformed XML and root aliases.

The saved JSON's input hashes identify the credited capture; later Taskfile edits
require another capture before crediting a new measurement. Native implementation,
timing, prompt safety, allocation peaks, binary authority and supported-VM acceptance
are intentionally unproved by these deterministic evidence checks.
