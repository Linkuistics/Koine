### Every exit and reservation

The operation ledger owns the exact branch traces. This assessment exercises
every fixed-file exit against its literal call count and the nine-call upper.
Parent-limit refusal spends one; named absence/refusal/oversize two; failed open
three; held refusal/oversize five; failed/short payload six; failed/extra EOF
seven; held change eight; named change/healthy result nine. A partial payload or
extra EOF byte is charged and never parsed. Named/held oversize does no input
read and retains the per-copy choice with affected metadata unknown.

Parser nil-data, nil-result, error, both-outputs, wrong type and key-count refusal
all reserve possible result/error releases first and retire actual owners.
No error-description copy is hidden. Directory descent failures retire acquired
children; fdopendir success transfers one close credit to closedir, while failure
keeps the caller's fd/close. No close retry follows an ambiguous error. Nil array/
string construction retires its acquired prefix; wrong/nil/foreign selector
result refuses without name rescue. Missing/empty name keys may advance; refused
keys/files/dictionaries cannot. Borrowers/plans retire before dictionaries, CFData
before input buffers, and selectors before their string owners.

Shared count/call/gross/deadline exhaustion freezes optional work and publication
as FAILED/null, with reserved actual cleanup still performed. Cancellation during
an outstanding call preserves inputs, output disposal credits and the shared
slot until actual return. Failure cannot turn a consumed read/copy/attempt into
an unused reservation. The existing ledger-check contests those branches; this
assessment adds arithmetic omission controls rather than another runtime adapter.

## Owned storage, gross and representations

The finite logical source reserve **6,816,128** is not a receipt ledger: its
512/256/64/32/128-byte records and two/four scalar-copy assumptions do not specify
how values are stored, bridged or projected. Its 1 MiB scratch cannot be added
again for file buffers or silently cover every temporary structure. CF objects
borrowed from retained dictionaries/arrays have no new ownership release, but
provider-created UTF-8 records, pointer-vector allocations/population and plans
do have charges. Created CF strings/arrays, parsers and source calls also acquire
opaque native memory whose peak remains unproved; this is not permission to
hide provider-owned projection as native memory.

An explicit scratch partition would need at least two 131,072-byte immutable
input arenas (information plus current name), two EOF-byte capacities, a bounded
key-conversion scratch and final-conversion scratch. A **candidate capacity
partition**, not a certificate, assigns 262,144 + 2 + 1,025 + 1,025 bytes and leaves
784,380 of the old 1,048,576-byte pool for walking. That remainder has no closed
per-branch walker/vector/record allocation plan. Alignment, allocator overhead,
independent component buffers, ownership overlap and vector capacities must be
classified rather than assumed to fit. The native CFData/plist/error/selector
peak is separate even when the no-copy input wrapper does not copy its bytes.

For any chosen representation the necessary calculation is:

`gross = sum(each owned allocation capacity) + sum(each performed read byte) + sum(each performed copy/conversion/vector-population write byte)`.

Storage/lifetime is the maximum simultaneously live owned capacity under the
dependency order; it never replaces or refunds cumulative gross. A freed or
reused input arena still accumulates each later read and every later write.
The input upper above closes only the read term. Literal direct components,
suffix-stripped keys, table-key projections, sorting/mapping/possible vectors,
preferences, every returned raw key, deduplicated/backstop plans and final
path/identifier/name projections need separate capacity/write/attempt receipts.
GetMaximumSizeForEncoding is not an allocation receipt or actual UTF-8 length.
One must specify bounded conversion, partial writes and overflow refusal, and
whether final storage is adopted or actually copied. No current scalar/array
implementation or measured Swift layout supplies those dimensions.

The 129-byte name and exact regional/table maxima remain useful evidence;
neither justifies truncating a name or claiming all observed CF value shapes
and final conversions successful. The preserved English Find My/Voice Memos
and German loctable witnesses still require useful native outcomes. An unresolved
known design term must be repaired before implementation, never relabelled as
a V-only serviceability question.

## Independent core response bound

For a string of n UTF-8 bytes and m selected occurrences, a conservative scalar
JSON bound is **m × (6n + 2)** bytes. The six multiplier covers escaping and the
two bytes are quotes. Every field/root alias or expanded fragment occurrence
counts separately, including repeated selected labels/locations/identifiers and
diagnostics. Selection keys themselves also need quoting/escaping and punctuation.
The literal path scalar alone, once per episode, has an upper **1,323,960 bytes**;
this is no full-response number and includes no claim that a path has a 256-byte
individual bound.

Complete wire derivation needs the actual selected document's field/alias
multiplicities, final ordinary/indexed scalar lengths, choices and source/fact
objects, null/enum/Boolean/number representations, all stored diagnostics and
fixed saturation/coverage/error/root overhead. Missing source tuples and final
scalar construction leave those terms unknown. The earlier 512-byte choice,
8,192-byte diagnostic and 65,536-byte root reserves have no complete encoded
schema/selection derivation here. Multiple roots or alias repetitions can exceed
8 MiB while a single profile fits; admission of up to 1,000 selections does not
prove every admitted response fits. Define and check the useful finite selected
profile and its alias controls without shrinking the public query language.

Current Engine source encodes through GraphQLJSONEncoder and checks the completed
body against RequestPolicy.version1.maximumResponseBytes. That protects what is
sent, not encoder peak memory, and cannot certify this finite population fits.
The graph's stale encode snippet/relationships were not used as current evidence.
No change to the core cap or policy version is selected.
