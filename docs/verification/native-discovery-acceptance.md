# Native discovery finite acceptance

**Design contract; every native G/N/V verdict is pending.**
The [spec](../specs/workspace-search.md) selects Foundation value lookup,
indexed/running/registration application sources and fixed-target settings
scripting. [Source declarations](native-discovery-sources.md) are not runtime
qualification. The existing public GraphQL (G), independently built actual
provider/host binaries (N) and signed supported TestAnyware macOS VMs (V) remain
the three agreed seams. Private source/clock/late-return substitutions test
contracts inside them, never substitute for native acceptance. No experiment,
permission request, launch or signing change was performed by this design.

The complete producer defines staged application populations and explicit cost
certificates, Settings two-sweep readiness uncertainty, and indexed long metadata.
Mandatory whole-producer review and any earned integration precede downstream
consumption. P1024, V12 and L1500 below require actual populous, cold/warm and
long-source/action qualification. All G1–G11, N1–N8 and V1–V13 verdicts remain
pending; no row passes from declarations, design checks or response stability.

most 200 bytes and at most 32 component visits. Construct/copy/sign via held
component-relative fixture directories outside Koine; no provider path substitute

NSMetadataItem, custom index database, different scope, hidden seed, client list,
registration-only copy or arbitrary predicate may stand in for those tuples.

reindex request on the short fixture parent, and independent captures at 10, 30
and 60 seconds after that preparation. These captures are outside a provider

The cardinality envelope is not a cap on a product's promised useful category;
it is the finite subject against which that promise must be demonstrated.

P1024 contains 1,024 distinct useful identifiers, including Dia, ChatGPT, Claude,
Zed, Visual Studio Code, Jump Desktop, Kimi, iTerm, Mail, Notes, Obsidian, Zotero,
Safari and Finder, plus 1,010 distinct signed UI test apps. Use actual app bundles
with independent native type/identity/metadata and registration witnesses, rather
than 1,010 names for one copy/identifier. They need not all run. Add 256 signed
agent/background/helper copies, including a checked nested helper, and 128 alias
spellings in the controlled source counterpart. Native alias exposure is qualified
separately rather than assumed from creating links; V3 stays independently pending
where its actual native precondition cannot be produced. AppKit/CF/preferred
registration lists each charge every returned slot, including repetitions.

The native VM keeps its existing baseline apps in the same measurement. The
finite construction leaves 640 distinct-spelling slots after 1,280 controlled
copies and 128 aliases; actual baseline/registration extras, source repetition,
identifier/choice counts and bytes must fit **all** gates. Record their full
independent manifest before capture. Record actual component visits including
link expansion, path/name/identifier bytes, and each source's native batch count;
the shallow certificates assume <=32 visits, <=256 path bytes, <=128 name/ID
bytes and <=128 running objects for P1024. These are qualification-subject facts,
not new public path/depth/string limits. If the supported VM baseline does not
fit, revise the declared subject/design explicitly; do not delete native apps,
omit helpers or lower the useful population to obtain a pass.

Prepare fixture installation, signing, indexing and registration explicitly
outside Koine's ordinary read. Observe the selected exact native sources from a
separate authorized observer and distinguish actual source omissions from the
provider dropping returned candidates. Compare every required identifier/copy
and fact against the independent manifest, not merely totals. Require several
non-running, non-witness indexed GUI apps, a running accessory and prohibited app,
and correct explicit true/false/missing/malformed flags in controlled counterparts.
All observed helper choices remain available for client-side filtering; optional
unknown flags neither erase a choice nor invent stopped-app runtime policy.

Finite size controls use small, populous and exact/beyond-envelope controlled
responses, reversed/permuted raw order, deep paths, long legal strings, repeated
same-ID copies and global exhaustion after staging useful choices. Deliberately
remove a useful non-witness, corrupt identity/eligibility, manufacture false flags,
hide helpers and publish a native-order prefix; each independent applicable
observer must fail. Native V11's all-useful requirement is separate from G10's
overflow behavior: an honestly failed catalogue still does **not** pass usefulness.
Actual unheld P1024 workloads and held late-return jobs use the existing independent
serviceability controls, fresh dialog/hydration subjects and new binary profiles.
No read registration, launch, source widening, raw walk or consent fallback is
permitted. Unavailable native populous conditions stay live before baseline.

At the shallow full envelope the owned-attempt certificate is 989,240, below
1,048,576. A fixed-record/payload construction reserves 512C spelling records,
256C choice records, 32U ordinal records, 128D identifier records, 128R running
records, two copies of each path and name/ID payload, 64×2,048 diagnostic bytes,
64C indexed fact records, two extra copies of indexed name/identifier scalars,
and 1 MiB one-walk scratch: 6,816,000 bytes. These are maximum **logical gross
charges** the actual adapter must satisfy, not a measured Swift/RSS bound. N5
accounts actual owned copies, record/container allocation and scratch before
relying on the certificate; unsupported larger allocations invalidate it.
One full items selection's conservative JSON certificate uses six bytes per
escaped payload byte, 512 fixed bytes/choice, 8,192/diagnostic and 65,536 for
root/coverage: 7,929,856 bytes. It fits the unchanged core cap; multiple selections
still charge the core's response materialization independently. Public maximum
strings need not fit these shallow certificates or the shared 8 MiB gate.

The deterministic design check proves these input/certificate inequalities and
rejects old 256-ID/16,384-call and broken copy/wire ceilings; it supplies no timing,
native enumeration, action-selection, memory-peak or useful-population verdict.

## Independent observers and serviceability

For V1–V3/V6–V8, use normally launched signed Koine and a separate authorized
observer. Establish a positive dialog control in a separate disposable consent
state that visibly produces the expected OS dialog; establish a cloud/dataless
hydration control with an independently observable before/after materialization
and provider transfer. Restore the native read subject's fresh state afterward.
An observer unable to see its positive control leaves that entire observation
pending. Ordinary accepted reads causing a consent dialog or hydration fail,
even if post-result filtering removed the choice. Only an explicit human action in Koine’s local explaining UI may request the
explained target-wide Automation consent; prepare/reveal may not. Independent
observers' Automation/AX authority is never attributed to Koine.

For actual native application/settings workloads and controlled blocked/late
adapter spans, run an independently recorded listener request stream, real grant
store transactions (including revoke/admission ordering) and unrelated authorized
launch/open/reveal action receipts/witnesses; pair with no-discovery references.
Declare finite cases: one job, four concurrent jobs, all four held then cancelled,
provider stop/start while held, query/AE late return, resource errors and budget
edges. Record socket acceptance/response latency/error, store transaction outcome,
actual action submission/acknowledgment/visible witness, and owned call/query/object
admission/return/release events in a fixed bounded sink. Sink overflow, missing
owner correlation, premature completion or resource failure invalidates that
measurement. A bounded synthetic listener failure, injected SQLite resource error
and failed native action must each be detected by its independent observer;
controls do not count as passing serviceability. Adapter holds prove ownership,
not that native API would block forever; unheld native workloads prove finite
outcomes, not opaque peaks/internal health. Unavailable native resource conditions
remain pending rather than guessed healthy. Do not restore the removed 72-credit
traversal, custom walker or system-find orphan accounts.

## Design verification and applicability

Freeze every checker input before/after, with per-file digest/exists/type records.
Use Taskfile design:search-compose then design:search-check for complete native
SDL, examples and retained actions, including removed-root, input/output,
foreign-provider-type, nullable-items and shared-object authority controls. Bundled,
update and refused-update profiles retain their exact separate subjects. check:docs validates relative
links and anchors with a deliberately broken control. Render all changed current
views with design:native-discovery-render/design:search-render and inspect actual
SVGs and browser topic/current panel/deep links/readability (dark/mobile where
tooling supports it). These checks supply no G/N/V native/binary pass.

Prior search-discovery/protected-path/descriptor/action/binary/serviceability
reports keep only their stated sources/builds/postures. The custom/raw/find reports
are comparison; their old parameters do not define the native API. Preserve
useful branch controls and independent listener/store/action observations by
re-expressing them over these exact sources. This contract replaces raw-backend
resource subjects; no live mixed task is pruned or credited by inference. Concrete
missing useful native choices go to the existing coverage decision before baseline.
