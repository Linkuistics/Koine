## Ownership and alternatives

Documentary API/source descriptions and earlier design references in the selected sections
are fixed historical statements of snapshot `93463d0a354570404028e92570c7079014c01bcd`.
They establish only what that document recorded, not possession of its complete original
bases or current SDK/kernel/runtime/image correspondence. Independent authors must retain
and accept each whole original basis and separately qualify actual required Q/P/A facts
before its consumer. Stable responsibilities below govern execution; retired designers
are historical sources and cannot appoint, accept, qualify or close a later operation.

One instrument owns bounded source acquisition, root/scope checks, file and
inventory observations, immutable byte packaging and the final evidence envelope.
It accepts the fixed permission contract and a new output destination; it does
not accept arbitrary query predicates, recursive roots, file lists or languages.
Its internal source/filesystem/decoder enabling points accept controlled pure
inputs during qualification. A separate verifier receives a frozen independent
expectation and packaged bytes; it never uses producer totals as its oracle.
The caller does not assemble layout traversal, parsers or race checks.

Original bytes and observations, decoder-derived facts, independent copy roles
and generated-copy rewrites have separate owners and records. Changing a decoder
cannot silently change original evidence. A reader flag cannot change a role.
Rewriting an identifier cannot inherit a source identity or digest. This keeps
capture mechanism, application purpose and construction policy independent.

| Representation | Caller knowledge and evidence cost | Decision |
| --- | --- | --- |
| Existing sizes/hashes and selected-name projection | Small packet, but callers must invent missing formats, candidates, branches and associations | Comparison only; it cannot recover bytes |
| Normalized parsed dictionaries alone | Easy reuse, but replaces original serialization and hides parser losses | Insufficient as the original evidence |
| Original byte objects, complete observations and separately qualified typed witnesses | Larger package and decoder verification; callers can replay each exact file and trace every derived fact | Selected contract |

The selected form would be reconsidered only if its exact permitted evidence is
unavailable or cannot be represented faithfully. That yields an explicit incomplete
boundary and remaining work, not a normalized substitute, smaller reference,
second target pass or automatic amount/posture change.

## Selected instrument architecture

[Components → Preserve original evidence and independent witnesses](../design/architecture/index.html#diagram-native-reference-instrument)
shows the proposed evidence-tool components and their inputs. It describes source
ownership and observation flow, not deployment containers or a qualified executable.

The selected implementation is one macOS command-line acquisition executable with
an in-process Core Foundation decoder, plus a separately implemented offline
verifier. Qualification supplies fake source and descriptor-operation adapters at
the instrument's composition point. The public packaging request supplies only an export;
the same retained Task/script/CLI chain receives a mandatory independently bound
SCRATCH/LIVE descriptor channel under the [entry contract](application-reference-packaging-runtime.md#retained-entry-and-domain-channel).
LIVE rejects scratch mappings and fixture authority. Arbitrary predicates, roots,
basenames, languages or adapter overrides cannot be selected by packaging callers.
Native decoder qualification reads
only independently authored pure bytes. This is an evidence tool, with no Koine
provider dependency, installed-app execution, registration or VM seam.

| Owner | Input and result | Hidden decisions / failure obligation |
| --- | --- | --- |
| Attempt coordinator | Fixed permission, qualified tool set, fresh destination → evidence envelope | Phase order, one writer, durable start, freeze and final decision; never retries |
| Source adapter | Fixed argument vector → raw stdout/stderr objects, slot occurrences and terminal event | Byte framing, concurrent pipe draining, actual child termination; no contents contact from an incomplete response |
| Held acquisition adapter | One admitted source occurrence → root/layout/inventory/file observations and bytes | Component lookup, containment, no-follow descendants, absence/refusal distinction and item closure |
| Native decoder | One immutable byte object → complete tagged native tree or explicit typed failure | Native type dispatch, format/error evidence and lossless export; no target pathname or conversion fallback |
| Independent verifier | Frozen specimen expectation and envelope → per-coordinate verdicts | Recomputes bytes, required occurrences, trees, branches, tails and associations; rejects producer-only totals |
| Admission verifier | Required inventory, complete proofs and actual retained artifacts → invocation-bound admission or refusal | Independent completeness, permission equality and image continuity; a producer success bit grants nothing |
| Independent bounded-evidence owner | Accepted B1–B8 inventory and independent expectations → scoped scratch/native/entry/read evidence plus named unknowns | Exact operation/object/interval/provenance and required controls; unobserved startup/service/proxy/right/map contact remains accepted risk, never full no-contact |

Compared with embedding parsing, traversal and mutation expectations in the legacy
Python capture, this arrangement gives the acquisition tool one deep external
interface and gives the verifier an independent oracle. A normalized plutil export
would simplify interchange but would add conversion/duplicate/type obligations
while still losing original serialization. Direct native decoding is selected;
its unqualified or unrepresentable branches remain explicit failures, not Python
type labels. The choice is reversible and earns no new ADR. These internal seams
implement the previously agreed pure controls, not a fourth product interface.

### Fixed source and terminal protocol

Invoke `/usr/bin/mdfind` directly with exactly `-0` and the predicate
`kMDItemContentTypeTree == 'com.apple.application-bundle'`, with no shell, `-live`,
scope/name override or interpretation option. The installed mdfind manual defines
`-0` as a NUL terminator after each returned path. Save the complete stdout and
stderr streams independently, their read errors, child launch/termination facts
and the exact argument/environment input. Drain both pipes while the child runs;
stdout EOF alone is not terminal success. A launched query requires both stream
closures and the reaped normal zero exit before contents acquisition may begin.
Nonzero exit, signal, pipe failure, missing reap or truncated framing cannot be
rescued by useful-looking output. Stderr is retained even on zero exit; its meaning
is not silently erased or turned into an index-health certificate.

For nonempty stdout, each NUL closes exactly one ordinal slot. The trailing
terminator creates no extra slot; consecutive terminators preserve actual empty
slots. Retain an unterminated suffix as an error fragment. Empty stdout at normal
terminal success yields zero observed slots, never all-disk completeness. Preserve
newlines, non-UTF-8 bytes, repeats and outside/malformed names without decoding,
trimming, sorting or deduplicating. NUL cannot be represented inside a result
pathname by this interface; bytes the tool never emits are not recovered by this
framing design. That source fidelity limit stays separate from losslessness of
the emitted byte stream.

The attempt declares one initial and one closure invocation of this same fixed
query. The closure invocation is an integrity observation, never a retry of a
failed initial response or a second source from which missing initial rows are
filled. An aborted attempt records unperformed closure work as unavailable. New
or missing slots, multiplicity, spellings and root associations are compared
item by item. Pure reordering retains both sequences and their permutation; it
does not fabricate raw-byte equality or alter later workload ordering.

### Held roots and the closed acquisition plan

Validate the literal absolute spelling's components against /System, /Applications
or /Library; `Applications-extra`, embedded NUL, relative paths and uncheckable
components do not authorize acquisition. Root resolution follows the existing
descriptor-relative kernel-semantics decision through search-only held directories,
with observed link expansions and directory identities, enforcing the canonical refusal
of outside intermediate operations with held common-ancestor entry. Classify the complete raw slot before any target lookup, then each component/observed
link expansion before its next operation under the [closed pre-lookup plan](#closed-pre-lookup-entries-and-operation-order).
Check both component-bounded scopes, exact reviewed class/operation entries, protected/
unsettled refusals and .app directory identity before listing/content handles. File aliases/non-directories remain raw source observations;
the tool never asks Finder or another application to resolve them.

Retain the ancestry/root handles and compare named-versus-held identities before
each descendant acquisition and again at closure. Probe every layout component
relative to those handles without following descendant links. A raced name cannot
steer an already held base to a replacement root; a fixed-file/base/locale link
or detected ancestry change refuses that occurrence before bytes are acquired.
Record the exact operation failure rather than reopening a changed name. These
checks establish their observation boundary; they cannot certify atomic placement
through an unobserved move-and-restore race, mount health or no opaque kernel
contact. Such limits do not justify a whole-path fallback or outside acquisition.

The ordered information/resource pairs are Contents / Contents/Resources,
Support Files / Support Files/Resources, Resources / Resources, and root / root.
Advance to the next layout only on established missing layout directories.
Denial, unknown type, link or lookup error stops selection with an explicit
unavailable/refused layout; an absent resource base does not select a new
information layout. Package the two information basenames at the selected
information base, the four name basenames at its resource base, and all six
basenames in every checked direct locale. Every probe gets a state record,
including absence. Coincident bases keep distinct logical roles even when they
share physical bytes. No executable, selected-language subset, indirect locale,
nested app search or other basename is acquired.

Inventory only the selected resource base's direct entries. Save returned raw
component bytes and ordinals, including structural dot entries if emitted; do not
descend into them. Classify Base, malformed names, non-locales, links, unknown and
non-directory .lproj entries with explicit reasons. Checked direct .lproj
directories, including Base.lproj, retain the complete six-file evidence; Base's
reader-selection branch remains distinct. Type checking never follows an inventory
entry link. Keep the raw sequence and any separate byte-sort permutation.

Open fixed regular files with no-follow semantics, compare named and held
device/inode/type/size/stamps, then stream to an exclusive evidence object through
exact EOF and recheck the held and named observations. Read failure preserves the
actual prefix/extent and error. A non-regular file is never opened for bytes.
At closure independently repeat the declared inventories, identities and exact
file reads and compare every associated item; equal sizes alone are insufficient.
The 131,072-byte reader branch is recorded without clipping larger authorized
files. A storage/allocation/I/O refusal retains its precise incomplete boundary;
this design selects no new evidence cap or production amount.

### Native typed decoder and fidelity limits

Select `CFPropertyListCreateWithData` with immutable results and its format/error
out-parameters, operating on packaged bytes only. Apple documents the
[data parser](https://developer.apple.com/documentation/corefoundation/cfpropertylistcreatewithdata(_:_:_:_:_:))
and [format cases](https://developer.apple.com/documentation/corefoundation/cfpropertylistformat);
the installed SDK declares OpenStep, XML v1 and binary v1 formats. This selects
the concrete route; actual XML/binary/OpenStep and .strings acceptance still needs
the frozen pure specimen programme. No header guess or file extension substitutes
for the parser's reported format. Keep original header/BOM/encoding evidence and
unknown/unsupported distinctions separately. An undocumented rejection cannot be
asserted to prove malformed input: retain the parser failure and an unestablished
format/validity classification until independently supported.

Walk the entire result using `CFGetTypeID`, checking CFBoolean before numeric
handling, rather than bridging to a language dictionary or NSNumber truth value.
Use ordered entry arrays for every CFDictionary enumeration and ordered arrays
for CFArray; record native enumeration as observed, separately from lexical order.
Export CFString as complete big-endian UTF-16 code units, CFData as exact bytes,
Boolean as its Boolean value, and CFDate as the decoder-observed binary64 absolute
time bits with its 2001 epoch. Strings are never normalized or repaired. Derived
UTF-8 lengths require an exact representable conversion; failure leaves that
length/branch unavailable while preserving the original code units.

For CFNumber, record its observed storage type, byte size and integer/real branch.
Export integer values as signed decimal strings only after exact public conversion
succeeds; verify reconstruction against the observed number. Real values carry
decoder-observed IEEE bits, including signed zero, infinities and NaNs, rather
than JSON numeric literals. Unsupported wider integers, native types or lossy
conversions make the typed observation explicitly incomplete and retain the bytes;
they cannot become a fabricated string value. Apple's
[number documentation](https://developer.apple.com/library/archive/documentation/CoreFoundation/Conceptual/CFPropertyLists/Articles/Numbers.html)
distinguishes stored numeric type from input representation. The export preserves
decoder observations, not a promise that CF preserves original integer width,
NaN payload, lexical date spelling or serialized key order.

Pin the acquisition/decoder executable digest, source and build inputs, compiler
and SDK identities, OS build and the runtime image identities obtainable through
the public loader. An unavailable identity is a stated qualification gap; an SDK
header or historical open-source CF implementation is not proof of the current
loaded runtime. Qualify duplicate serialized keys separately for each admitted
format, preserving original bytes and independently authored duplicate positions,
the observed surviving native entries and resolution/coercion limits. Never claim
the semantic tree contains serialized duplicates. A format or duplicate branch not
qualified is explicitly unqualified; changed images invalidate the affected proof.
Design text supplies none of those identities or observations; require their original qualified evidence before crediting the corresponding claim.

## Proposed envelope version and verification interface

The selected envelope version is `koine.application-reference-evidence/1`.
Its executable field schema and exhaustive validator must be materialized and
qualified during construction, before any target acquisition. It has the following
closed record kinds; implementation cannot silently omit a field group from the
earlier [required record model](#evidence-records-and-association-keys).

| Record kind | Closed payload and relationships |
| --- | --- |
| attempt | Permission digest, reference/build, declared phases, tool/input identities, intervals, terminal result and limitations |
| source | Phase, raw stream object references, framing, launch/reap/read outcomes, all ordinal slot bytes and root/reason links |
| root | Source occurrence links, literal/resolved bytes, scope/ancestry/link observations, before/held/after identities, layout/base observations and copy/alias relations |
| inventory | Root/base/phase, raw entry ordinals/bytes/types/classification, stamps, sorted permutation and complete/error outcome |
| file | Root/base/locale/basename role, every probe state, named/held/after facts, complete/prefix extent, object and decoder links |
| decoded | File/object/tool coordinate, original-format evidence, parser format/error, complete tagged tree or exact incomplete coordinate, duplicate/coercion qualification reference |
| branch | Exact file/tree coordinate, named candidate/flag/version/table/LocProvenance branch and full associated tagged value where present |
| tail | Exact root/file/entry/tree coordinate, byte or code-unit measure, representability and branch/selection relation |
| closure | Per-item before/after differences, object/record digests, missing/unavailable work, input/image stability and separate byte/typed/association verdicts |

Every record has version, kind, packet-local coordinate, phase and an explicit
outcome. Outcome variants observed/absent/refused/unavailable/error each have
closed required fields; missing keys are schema failure, not null absence. Native
parse failure has its own decoded outcome. Foreign fields or variants are rejected
at every nesting level; a future extension requires a recognized new version.
JSON duplicate member names, lossy numbers, dangling references and ambiguous
coordinates are errors. Arbitrary original dictionary keys live as typed entry
data, not envelope schema extensions.

Use canonical padded base64 for all raw bytes and UTF-16 units; lengths and
nonnegative ordinals use exact integer encodings. Native integers use decimal
strings and floating/date bits use fixed-width hex strings. SHA-256 references
bind complete immutable objects; partial objects carry prefix length and outcome,
never the complete-file digest. Ordered occurrence arrays preserve repetitions;
canonical JSON object-key ordering does not sort those arrays. The closed tagged
tree variants are dictionary, array, string, Boolean, integer, real, date and data;
an unsupported native type cannot masquerade as a successful tagged extension.

Coordinates include source phase/ordinal, root observation, base role, locale raw
component, basename and tree path. Tree paths identify array positions or dictionary
entry/key code units; an independent comparison may match dictionary members by
exact keys while preserving the observed enumeration separately. Same identifier,
same digest or equal-length tail never merges copies. Physical aliases require
checked root identity and observed relationship; every repeated source occurrence
and helper/alias-target fixture still has complete logical file/branch/tail links.

Helper is an independently authored pure specimen role at this boundary, not a
native helper-purpose or inferred nested-containment field. Current per-copy purpose
is independently established after capture. Helper controls mutate its actual
source/file/tree/tail coordinates; physical alias controls use checked root identity
and occurrence links. Nested bundles are separate emitted slots, without traversal
or an invented containment edge.

The verifier takes two inputs: an immutable package and a separately frozen
expectation. It validates the schema and recomputes byte lengths/hashes/format
evidence, complete required occurrences, tagged trees, reader branches and tail
associations against the expected specimen. The expectation is authored before
the producer runs; no producer report, decoder rerun alone or copied producer tree
supplies it. Binary/XML/OpenStep positives include hand-authored known values and
explicit unsupported/malformed/duplicate limits. Counts are diagnostics only.
Every mismatch reports a stable record/tree coordinate and expected failure class.

### Permit receipt and explicit initialization

The fixed subject has two reserved permit names, `unspent.receipt` and `spent.receipt`,
an immutable authority event `consume.intent`, and one original evidence child, `attempt`.
They are siblings: deleting `attempt` never deletes a permit name or the authority event.
An export is outside this subject and cannot select it.
Only the exact independently validated **unspent** name authorizes consumption. A spent
receipt has the same bytes and held-file identity, but its name grants no permission.
Both names present, neither present, an unreadable name, any `consume.intent` from an earlier
invocation or any unexpected initialization prefix refuses. Packaging never copies a spent receipt back, creates a missing receipt,
scans for a relocated subject or interprets a partial initialization as first use.

The closed receipt contains version, stable one-pass permission identity, initialization
nonce, exact absolute subject and actual UID, held subject/ancestor and receipt-file
identities, permission-profile identity, approved anchor **issuance revision**, and synchronization
contract identity. File identities include device/inode/type and available creation stamps;
controlled authority directories are UID-owned mode 0700 and regular receipt files 0600,
with no symlink or extra hard link. Ancestor ownership/modes are independently validated
against their actual approved observations, not assumed to equal the user's UID. Receipt
bytes never contain their own digest or a qualification-output digest. The separately
anchored validation record must bind their exact bytes and actual file identity; matching
producer-generated hashes cannot supply that record. The independent human acceptance
owner owns the trust root and correction channel; qualified provisioning and separate
validation supply the non-circular bindings.

The receipt's permission-profile identity names the complete frozen **issuance profile**,
not a mutable alias for the current profile. Admission compares it exactly with the
externally accepted issuance payload. It separately compares actual current extracts,
concordance and full profile with the highest accepted current payload. Without a
correction, the two profile identities must be equal. With a correction, the external
bridge must bind both complete profile identities and their independently reviewed
field/clause correspondence, as specified below; no receipt field is silently superseded.

Provisioning is a separate explicit one-initialization operation under that approved
channel. It cannot be invoked by packaging or a pure selector. It exclusively creates the
selected subject and staged receipt, records actual identities, and requests independent
validation of the complete closed receipt and selected approval revision. Existing subject,
staged prefix, missing approval or uncertain prior initialization refuses; there is no
automatic recovery/recreation. The validator must establish the proposed final unspent
role and publish its externally anchored binding before the initializer exposes that name.
Exclusive same-directory publication preserves the staged receipt's checked inode. Then

### Persistence operations and their evidence limits

Use exclusive `mkdirat` and `openat(O_CREAT | O_EXCL | O_NOFOLLOW | O_CLOEXEC)` for new
evidence, complete checked write loops, exact EOF/length/digest validation and held-file
identity checks. Positive short writes advance only by the actual count; zero/error stops
and preserves the extent. No failed flush, rename or acquisition is retried by default.

For each published regular receipt/intent/header/object/segment: finish writes, check its bytes,
call `fcntl(fd, F_FULLFSYNC)` and require success. For each namespace mutation: require
`fsync` on every affected held parent directory, then `F_FULLFSYNC` on a held regular file
on that same device, and recheck the changed names/held identities. For permit consumption
that regular file is the spent receipt. For subject/attempt/export creation and later
publication it is their checked receipt/header/object. Initializer also synchronizes each
created ancestor's parent in creation order; it never treats a directory close as flush.
Keep raw return/errno, descriptor/device association and operation order in evidence.

The selected assumption is explicit: the local filesystem supports these operations,
directory synchronization covers the specified namespace mutation, and the following
same-device full flush orders it before release. Pin the actual filesystem/device
description and independently reviewed API/source basis; scratch successes alone cannot
establish that assumption. Unknown support/basis, a failed acknowledgement, changed device
or unavailable identity keeps admission unavailable. No network/cloud/removable substitute
or fallback to plain fsync is selected. Current APFS support and namespace semantics
remain an actual provisioning/qualification obligation, not a fact established here.

Apple's archived [fsync manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fsync.2.html)
describes host flushing and the power-loss/reordering gap; its
[fcntl manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fcntl.2.html)
describes a device-cache flush request and hardware limits. Neither supplies a current
APFS directory-crash certificate. Apple's pinned
[rename manual source](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/man/man2/rename.2)
states descriptor-relative rename and exclusive-destination semantics on supporting
filesystems; it is an API/source basis, not evidence of the reference kernel. The archived
[flock manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/flock.2.html)
supports cooperative nonblocking exclusion and warns about inherited lock references.

Scratch controls demonstrate actual API acknowledgements, ordering, exclusions and
**process-death retention** on their frozen filesystem. They never demonstrate OS-crash,
kernel-panic or power-loss persistence. The k270-accepted bounded namespace/full-flush
assumption and unobserved storage/hardware failure remain limits, not a universal at-most-
one-across-power-loss claim. Unsupported required semantics receive precise live work
before k245; no VM, root collector or strengthened store is authorized by that gap.

the final record is complete, the exact current independent validation/acceptance required
by the phase occurs and all other chain/identity/control rules hold. They cannot replace
a missing earlier original, attest past flush/EOF/reap outside the exception or infer
no dispatch/provisioning. A known receiver loss, contradictory terminal evidence or an
incomplete final record is a failed/unknown tail, not this clean retained-content case;
it cannot be advanced as successful publication. The [failed-boundary host table](#failed-boundaries-and-their-exact-checkpoint-hosts)
places fresh content-only comparison and non-success disposition before a successor
or authority use; loss of a disposition's own batch stops as specified.
Neither fresh acceptance nor later readable files can turn that tail into proof of a
former completion or never-started initialization. Undetected receiver loss with intact
content is exactly the accepted risk, not a promised detection capability.

Loss propagates by endpoint closure at each declared enabling point. No new PID/daemon

that fact. Native work already issued retains its true-return limits. Locks and original
streams stay owned through actual descendants' return/final freeze; lost ownership blocks
the next consumer. A pending publication tail disarms and has no older-success fallback.
Only the independently accepted disposition/successor route may advance failed chains.

##### Finite publication when the carrier is damaged

Ordinary recovery uses the accepted publication.intent-before-writer envelope. There is
one explicit **ordering exception**, needed when launcher-events or publication-events
itself has a failed reachable tail, or when first-seed/container failure leaves their
initial carrier unready. Requiring its successor intent before disposition would require
the finalized disposition as that intent's own earlier predecessor. Moving the act to
a sixth checkpoint would not break this dependency. Use the following bounded prefix
inside the same hosted repeat; no earlier-original retention duty is relaxed.

1. Before any recovery write, independently prepare/review/control and accept the exact
   receiver/final-recorder/launcher/registrar/independent-comparison mechanics and **finite
   closed list** of pre-intent carrier dispositions from already observed failed
   publication/launcher tails, separately from the complete failed cut. Each disposition member
   must be independently established absent under its held parent, with the expected
   original extent/identity intact. The prelude freezes the entire cut, names the host
   and prohibits ordinary reads/effects, new initialization, successor work and skipped
   ordinals. No chain scan, guessed slot or recursively discovered cut is admitted.
2. After the host's direct ready act, start the accepted receiver → final recorder →
   launcher → disposition-writer tree. Until the carrier is ready, the final recorder
   and launcher retain actual events in bounded memory, as at first seed reservation.
   Only the disposition-only registrar may publish the listed **existing-slot**
   failure.disposition members; it creates no new ordinal, permit, payload or record
   elsewhere. Use release-before-register leases, independently checked identities and
   actual write/flush acknowledgments. If the first seed/locks/containers were never reserved,
   CP01's fresh exact A2/ROOT plan must first authorize only their exclusive missing
   reservations; existing objects are checked, never recreated or repaired in place.
3. For each prefix disposition retain the earlier direct act, disposition.published,
   full actual bytes/held identity/write/flush returns, independent current comparison,
   and launcher's actual writer EOF/normal zero reap. The accepted independent factual
   comparison uses the existing held-stream/engine interface; its original results and
   returns are also retained. No validator writes into a damaged validation chain merely
   to authorize this prefix. Launcher.event conveys these reached originals to the final
   recorder. Its publication.stage WRITER_RETAINED may acknowledge **only this declared
   recovery prefix before publication.intent**. The frame states that the evidence is
   memory-retained, with its exact cut/plan/nonce, and promises no future durable record.
4. That is current-stage finalization **within this one live recovery batch**, after the
   disposition writer's actual return. Only now reserve the immediate publication-events
   successor (or first exact slot) with its predecessor disposition's full bytes/identity,
   prefix events and the original direct plan as earlier inputs. Publish/acknowledge
   publication.intent and publication.ready. Then reserve the immediate launcher-events
   successor and record the complete earlier prefix there. If release-events also failed,
   its disposition uses the now-ready ordinary envelope and remains DISARMED; a new fully acknowledged disarm
   successor precedes all ordinary changed work or Q. No old eligible event is usable.
5. The same batch completes every other disposition in the frozen complete cut through the ordinary
   envelope, retains every prefix/writer/comparison/launcher original in its final record,
   and reaches the unchanged final-recorder/outer endpoint. Before **any external successor
   or ordinary checkpoint consumer**, independently check the complete current byte/member/
   identity/provenance join and each disposition. In-memory stage finalization is never
   a transferable predecessor, a saved continuation or credit at a later checkpoint.

No earlier record names that future final record. Its new intent names already reached
prefix facts; its terminal record later retains their actual originals and launcher reap.
This is an explicit extension of the first-reservation/current-stage ordering rule, using
the existing closed kinds, channels and write locations. It gives the final recorder no
disposition authority and the registrar no transcript/close/initialization authority.
Independent prefix bounds, frames, strict reader and the source-rooted recovery plan must
qualify together before use. Overflow, missing required prefix original, failed comparison,
unknown held identity, lost lease/owner/endpoint or nonzero/missing return stops before the
next enabling point. No timeout cancels an issued operation or releases its ownership.

**The prefix has no recovery prefix of its own.** If its disposition or archival join
fails, preserve all reached members/frames and null missing originals and stop before
successor. A present partial/unknown disposition is neither overwritten nor disposed
again, skipped by another chain/ordinal or copied to an alternate store. Even complete
disposition bytes cannot supply a missing earlier acknowledgment/reap. If only this
disposition batch's final receiver observation is known lost, current content may be
inspected offline, but this design does not advance that unknown disposition batch.
Its exact unavailable boundary and the trade-off between retaining refusal and separately
authorizing a concrete recovery mechanism return to Antony **before** any such consumer.
No new ceremony or authority for that unresolved actual case is presumed. An ordinary
record's known receiver loss, with no failed disposition yet, uses the hosted in-slot
disposition route below; it never reconstructs the old terminal event.

##### Publication and recovery dependency expansion

The following closes the consumer/read interpretation of the existing contracts. It is
design notation, not a new schema, record kind, permission or executable proof. Expand
each finite accepted member/role vector in its frozen order. Every arrow requires the
actual earlier result; all incoming edges are conjunctive. A later reader's association
of two completed records is a **read join**, never an input to either record's production.
No topological order, matching content or missing name proves original history.

**Closed read closure.** Once the register exists, the prelude traverses all eight chains from 0 through exact
immediate successors and preserves every admitted absent-next observation. The generation,

failure.disposition}` is an explicit supporting-predecessor read, with the conditional
disposition and close-only writer rules intact; it is not an arbitrary earlier locator.

ordinary consumer. Unsupported kind,
missing association, extra/missing member, failed tail or unknown required absence refuses
ordinary selection. Source re-entry and intact-anchor recovery retain their exact limited

##### Source-rooted prelude before selection

**Reference Checkpoint Prelude** owns the pre-tool enabling point. It is a separately
authored, reviewed, read-only native artifact supplied with independent original source,
build correspondence, complete required runtime/read/image facts and original controls.
It is separate from the acquisition/admission/registrar candidates and their producers/

anchor. The holder acquires no selection or authority-writing capability. Read-only
means no mutation of retained inputs, register or authority; private unnamed-pipe plan/
result output is permitted under the closed descriptor protocol, never filesystem staging.

The one-page **source/OS method** fixes the prelude's exact independently retained
executable original, original source/build/control evidence, literal invocation and
finite OS/runtime assumptions. That original is supplied independently **before CP01**,
outside checkout/proofs/exports and outside every anchor/revision being selected. It is
not selected by a register pointer, argument, environment, PATH, candidate manifest or
an old `trust.continuity`. Its exact ancestor/component/identity/read plan belongs to the
independent retained-input inventory, with no listing, resolver or discretionary read.
Required actual locators/identities remain unacquired until independently supplied and
accepted; a documentary name or digest grants no access or original possession.

At CP01-SOURCE and at the existing continuity start of **each CP02–CP05**, Antony uses
that original source/OS method before invoking the original prelude. He explicitly trusts
the independently supplied original and the named OS primitives on their source/build/
original-control grounds; this is the finite human/OS trust root, **not** an automated
proof of its own execution. No executing prelude, holder or candidate may certify that
first trust judgment. A stored register copy is never the prelude's root. The retained
native executable original has its separately approved executable mode; the 0600 rule
still applies to authority records and anchor originals. No unchecked executable copy,
interpreter substitution, compilation or dependency resolution occurs at this step.
Required current image/read correspondence stays independently required before its
claimed consumer/credit; source trust waives no Q/P fact and claims no recursive OS proof.

Missing, changed, substituted, uninspectable or unestablished source-root originals,
required runtime/image evidence or original controls make this checkpoint unavailable
**before prelude execution**. They do not permit a candidate to reconstruct the root.
The original supplier's independent original/byte/identity and source/build checks must
detect accidental root replacement; matching a label or a candidate-generated hash is
insufficient. Undetectable wholesale original/OS forgery and mutate/restore races retain
the existing cooperative limit, distinct from detected accidental replacement. Re-entry
uses newly ready independent source/OS originals at repeated CP01 SOURCE/ARTIFACTS;
no new checkpoint, saved ROOT authority, old-anchor fallback or initialization follows.

##### Holder execution and closed descriptor handoff

**Reference Stream Holder** retains the exact original/copy streams and their namespace
identity checks. Its original remains a single-link 0600 regular anchor record; its
separate executable copy has its own exact approved mode/identity. For every planned pair,

`fstatat(..., AT_SYMLINK_NOFOLLOW)` equality. OS-object modes/ownership use their separately
approved facts. No pathname shell redirection or matching digest replaces these checks.

The prelude first compares the **executing holder copy**, not just the entry, against
its independent original and required runtime/read closure. A rebuild, even with the same
label and same source, is refused on changed bytes/identity/closure before holder launch.
It launches only that literal approved executable location with the accepted explicit
spawn/descriptor actions. This design claims no descriptor-exec primitive or atomic
binding of pathname launch to the held inode. Independent current finite peer/image/
incarnation/backing checks, named/held checks and before/after bytes remain required;
substitution between comparison and execution freezes before entry/engine effects. The
selected k295 observations may be unavailable and share race/OS/cache limits. A pre-exec
file hash, reported pathname or PID alone never supplies executing-image correspondence.
The independently retained factual observer and its original source/build/runtime/control
closure are earlier source/OS-method inputs, not an anchor-selected candidate. It uses
only the already selected finite declared same-UID peer metadata; no new scan/API/PID
scope is authorized. The parent withholds the holder's fd-3 plan while that observer
checks the newly spawned holder. The holder waits at that read before its planned file
opens or child execution. Missing/wrong/changed image/peer facts close the plan pipe,
freeze and retain true-return/death extents; they never release an empty default plan.
The same withheld-input rendezvous applies before each newly executing entry/consumer's
planned effects. This bounds the declared programme's enabling point; it does not undo
loader/constructor effects or establish complete pre-effect no-contact coverage.

All comparison children use retained `/usr/bin/cmp` with exactly
`-s /dev/fd/3 /dev/fd/4`; the exact cmp executable/source/OS/runtime/read assumptions and
required image facts are independent prelude inputs. Compare original/copy, then the
reverse order, with otherwise identical closed arguments, no PATH or pathname reopen.
Normal zero status and actual zero reap are required. Unmodified cmp emits no application
result frame: do not invent a cmp status-channel acknowledgment. Its stream-read/EOF
evidence comes from the qualified operation observations and entry's complete reads.
A cmp process has no application authority or input paths beyond these two
already held streams and its exact runtime plan. The prelude checks the holder; the
holder checks the entry; the checked entry compares the remaining checked streams.

The fixed handoff is **one pair per sequential read-only child**, avoiding a dynamic
inherited descriptor range. Complete member ordering is the independently frozen opaque
member-ID vector. Its exact set/count/length bounds and all required actual descriptors
must be ready before the first candidate comparison; exceeding a qualified limit refuses,
never drops members or opens them lazily after candidate execution.

###### Selection within an open bracket

Every correction needs a fresh disarm, so several batches can run between two checkpoints.
This subsection fixes how a later invocation and the next checkpoint treat them. It adds
no record kind, writer, checkpoint, human act, observation API or authority; the one new
binding is a field set in an existing record.

**Batches on the shared chain.** Every publication invocation appends exactly one
`publication-events` slot. Its finalized publication.intent names either a checkpoint
purpose, making a **checkpoint batch**, or one of the three closed kinds above, making an
**inter-checkpoint batch**. A batch's members are its publication slot and every slot on
any chain whose intent binds that publication.intent; its publication.terminal lists
exactly those. Batches are therefore totally ordered by publication ordinal, and each later
batch binds the earlier batch's publication-events and launcher-events slots as its
finalized predecessors. The **bracket base** is the latest checkpoint batch whose
publication.intent is finalized. The **open bracket** is every inter-checkpoint batch after
it, in ordinal order; it may be empty.

**The record each checkpoint visit keeps.** Every checkpoint batch's publication.intent
binds that visit's E1 held source-root original identities (prelude, factual observer, cmp,
runtime) and the classification of each inter-checkpoint batch between the previous
checkpoint batch and itself: ordinal, kind, result and, for a failed cut, its one host.
The vector is empty when there is no such batch, always so at initial CP01. Every write at
a checkpoint happens inside such a batch, including a repeated CP01 visit without ROOT, a
recovery-only host and a carrier-prefix host, so every visit that writes anything keeps
this record. A visit that writes nothing keeps nothing: its E1 is no base, it consumes
nothing and the bracket stays open for the next visit, which compares against the base. A
finalized intent remains the record of its visit's read even when a later writer of that
batch fails and is disposed. cp01.source and trust.continuity copy the same identities, and
trust.continuity the same vector; a copy that differs from its batch's intent is a failed
join.

**Selection order.** Every prelude, at a checkpoint or between checkpoints, selects in this
order, and no step reads a later step's result:

1. The closed traversal of all eight chains, unchanged.
2. Batch partition: base, open bracket and each slot's batch, from closed purposes, kinds
   and intent bindings alone.
3. At a checkpoint only, root comparison: this E1's held identities against the base
   intent's identities and each open batch's bound E1i observation.
4. Anchor selection from `anchors` and bootstrap-validation slots only. Anchor applicability
   uses the anchor's own bound disarm/correction basis against slots outside the open
   bracket. No revalidation slot, open-bracket slot or classification is an input, so a
   revalidation of any status neither selects nor blocks the anchor.
5. Classification of each open batch against that anchor: E3b at a checkpoint,
   `BRACKET_OPEN` between checkpoints.
6. Kind and ordinary selection, using the recorded classifications of closed brackets and
   step 5's classification of the open one. The current disarm generation for a consumer is
   chosen only here.

**Between checkpoints.** An open batch is `BRACKET_OPEN` when its U-graph join is complete
under `UNARCHIVED_BY_RULE`, no member carries a disposition, it binds the same anchor and
revision as step 4, it is the immediate successor of the base or of the previous open batch,
and its kind was admitted under the table below at its position. Anything else is a failed
or partial tail and refuses before any write. This is a structural check only. Between
checkpoints the one identity comparison is E1i's own check of the source-root originals
against the supplier's independent identity record. No step compares an identity
observation or E8 result with the base intent's root identities, cp01.source,
trust.continuity or another batch's observation, and none produces `BRACKET_VERIFIED`,
`SOURCE_REENTRY_REQUIRED` or a failed cut.

| New invocation | Admission while the open bracket holds earlier batches |
| --- | --- |
| `DISARM_MAINTENANCE` | Admitted after any open batch. After an open disarm, that slot is its release predecessor, so successive corrections chain. After an open close, the close is stale for CP04, which already refuses a close older than the newest disarm. After an open revalidation, it binds the unchanged accepted receipt basis, which that revalidation does not alter. |
| `RECEIPT_REVALIDATION` | Admitted after open disarms only; its validation.intent binds the latest as its current disarm. Refused after an open revalidation (one per bracket, for one CP02 acceptance) or an open close (a close binds an accepted receipt basis; a revalidation exists only for one in CP02 recovery). |
| `DISTINCT_CLOSE` | Admitted only as the first batch of its bracket. An open disarm is newer than its CP03 generation, an open revalidation leaves its receipt basis awaiting CP02, and a second close would supersede the first before CP04. |

Shared chains always take the immediate predecessor; that binding is chain order, not use
of the earlier output.

**Predecessor admissibility.** A kind-chain or shared-chain predecessor is admissible only
when it is finalized and is one of:

- a slot written or disposed inside a checkpoint batch, including a hosted failure.disposition;
- an inter-checkpoint result that its closing checkpoint batch recorded as `BRACKET_VERIFIED`;
- a `BRACKET_OPEN` slot, for exactly the uses the table admits.

A batch recorded as not verified is admissible only through its finalized in-slot
disposition; its undisposed result, a partial slot or a failed disposition refuses. A fresh
disarm after a hosted disposition therefore takes the disposed slot as its predecessor.

**Verification at the next checkpoint.** Step 3 compares the root. Any byte or stamp
inequality with the base intent's identities or any open batch's bound observation returns
`SOURCE_REENTRY_REQUIRED` for the whole open bracket. With an intact root, step 5 checks
batches in ordinal order. A batch is `BRACKET_VERIFIED` when its bound anchor,
member/image/runtime/read vector and writer identities equal that anchor's trust-originals
and accepted capability plan, its kind and predecessors satisfy the rules above at its
position, and its complete U-graph join holds under `UNARCHIVED_BY_RULE`. A later checkpoint
reads a verified result from its closing batch's record; it never re-verifies a closed
bracket.

**Cut extent and its one host.** A root break makes the whole open bracket one cut,
hosted at repeated CP01 SOURCE/ARTIFACTS. Otherwise batches before the first failure stay
verified, and the first failing batch and every later batch form one cut: every slot of
those batches on every chain, a suffix of each chain's bracket slots. A later batch is
carried because it bound the earlier batch's shared-chain slots, and possibly its disarm
as its basis. The cut has exactly one host: the earliest, in CP01, CP02, CP03 order, of
its batches' kind hosts (disarm at CP03, or CP01 when its bound disarm.intent scope alters
trust/rules; close at repeated CP03; revalidation at repeated CP02). This applies the host
table's whole-cut rule to a bracket. The cut always ends at the publication-events and
launcher-events tails, so the host uses the
[finite carrier prefix](#finite-publication-when-the-carrier-is-damaged) for those two
tails and the ordinary envelope for every other cut slot. A visit that is not the host
cannot write, so it refuses before any write and the bracket stays open. A cut recorded by
a host batch whose dispositions did not all finish binds every later visit until each
member is disposed, under the failed-disposition stop where it applies. Each kind's trust
consumer stays at its own checkpoint, and fresh successors run as new inter-checkpoint
invocations after the host's batch.

| Every checkpoint batch's intent binds its E1 identities and classification vector, including repeated CP01 without ROOT and a recovery-only host; a visit that writes nothing leaves the bracket open | Omit or alter the identities or vector, let a cp01.source or trust.continuity copy differ, compare against those copies instead of the base intent, or treat a write-nothing visit's E1 as a base: failed join, refused at E3b. |

| Between checkpoints the only identity comparison is E1i's | A gate compares an observation with the base intent, cp01.source, trust.continuity or another batch, or writes any classification: refuse at that step. |

These are further required Q07/Q08/Q10 and relevant Q05/Q09 controls under the same
exclusions. Required originals/identities remain unacquired.

## Original bytes and complete typed witnesses

## Freeze and replay limits

For every acquired file compare named and held identities, measured size, actual
read extent, exact EOF and post-read status, then independently recheck the complete
inventories and associated file bytes at closure. Preserve item-by-item before/after

package claim. Pin **all** measurement inputs before/after, including verifier,

GUI template. Missing/refused/unknown evidence cannot satisfy the complete finite
subject. A well-formed failed attempt envelope is not a successful package.
