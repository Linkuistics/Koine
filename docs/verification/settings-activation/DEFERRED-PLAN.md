# Default deferred acquisition: one fresh guest

Declared on 2026-10-28 before the first deferred guest. Run exactly one new clone,
`koine-k12-deferred-01`, through `task app:vm-settings-deferred CLI_ARGS=01`.
Every started clone consumes the slot, including preflight/transport failure or
interruption. No replacement, repeated action after failure, or cap extension.
All diagnostic/order/native/context/events samples remain closed.

Use the unchanged signed `.build/settings-activation/events/Koine.app` and the
existing headless dump requester, with the memory preference enabled and legacy
file tracing absent. The wrapper inventories that exact bundle; it does not
build or modify it. The original call order/NSApp API and the four Settings
input/front/focus assertions stay unchanged. Use the same macOS 27 golden image,
1920×1080 and settled TextEdit precondition. Stop at the first assertion failure.
These are matched scenario conditions, not a randomized causal/load comparison
with the earlier live-logger guest. No claim follows from differences in counts.

Do not start a native log reader, debugger or logging-configuration mutation
before/during the scenario. Save the installed guest's public `log help
collect/show`, read-only `log config --status` and process list before launch. Root reads use the disposable golden
admin/admin test account. Help exit 64 is retained as usage, not an acquisition
failure; any other unexpected help exit fails preflight.
After observations, preserve untouched failure screenshot/native/windows if the
scenario failed. Then issue one raw `log collect --last 10m` as root, into a new
archive, with a 120-second exec bound. Save start/collection timestamps. Render
only afterward, using `log show --archive --style ndjson --info --debug` and the
unchanged qualified reduced predicate. Preserve the full raw archive locally,
its digest, a file inventory, rendering/error output and every raw transport.
Package on EXIT even if acquisition/rendering fails, retaining acquisition and
packaging status separately. Download individual partial files even on failure.
If the primary archive download fails, permit exactly one packaging-only recovery
request/download of the existing directory to a separate recovery archive. Preserve
that raw failed request (intentional exit 1) and never repeat `log collect`.
Recovery cannot turn the original acquisition/collection into success.

Only after native acquisition/download, request the bounded memory dump once,
retaining its independent files and raw envelope. This cannot repair focus.
The inherited safe-read retries remain; new preflight/acquisition/dump and final
endpoint transports are single attempts. An unsuccessful envelope remains so
even when its returned text agrees. Cleanup always stops the clone and validates
its stop envelope. Retain every scenario/Task/collection/audit/stop status.

Before launch, freeze the completed candidate's full regular-file/link inventory,
all source/manifests/lockfiles, signing/build inputs, Taskfile, every consumed
scenario/helper/observer/predicate/dump source and binary, and this protocol.
Finish golden config/disk/NVRAM hashes before starting the clone. Compare the
same subjects after collection and at sample end. No measured input changes
under a run. Collection files are copied without rewriting their contents.

Apple's [logging guidance](https://developer.apple.com/documentation/os/generating-log-messages-from-your-code)
and [WWDC20 persistence explanation](https://developer.apple.com/videos/play/wwdc2020/10168/)
say recent Info may be collected while unconfigured Debug is discarded. Default
retention is bounded by memory/storage and activity; `--last` requests a time
range, not guaranteed completeness. `--debug` is a display filter, not retroactive
enablement. The historical native client `SLSSetFrontProcessWithInfo` is Info;
launchservices token and some WindowServer detail is Debug. Missing rows cannot
establish absent requests, refusal or external ownership.

Acquisition qualification needs at least one positive actual-Koine client record
inside its buffered activation interval, correlated by PID/clocks, plus available
native disposition and independent focus observations. Report each observed
selection individually, including unmatched intervals and collection lag. Do not
infer full four-action retention from a final successful join. Qualify the reader
against retained known-positive historical rows and a missing/wrong-PID control;
those offline checks are not a new native sample. Loss reports, absent Debug and
redaction are explicit limits. A failure reproduced with this exact configuration
can qualify symptom preservation; green observations cannot. Removing the live
reader still leaves buffering, notifications and ordinary system logging work.

This prefix has no resize, scrolling, shortcuts, client requests/consent, silent
launch, running-app reopen, login restart or Quit acceptance: all remain NOT RUN.
No product repair is selected here. Every original positive causal discriminator,
justified repair/failing seam and separately predeclared frozen complete ordinary
acceptance duty remains. If the acquisition boundary is useful but those duties
remain larger, decompose at that verified boundary with the next precise question.
Do not repeat unchanged instruments to chase a failure. No release/notarization
or upstream report.
