## Return package and admission gate

The evidence owners return one immutable, privately retained package. Do not put
environment values, VM credentials or native captures into public issue text.
Each return identifies its claim, subject, source basis, observation method,
finite input and output limits, actual result, limitations and dependent rows.
Bind source archives and binary/fixture digests before work and verify them
afterwards. Preserve originals and every partial, including failed observations.

Before requesting execution, a reviewed manifest must fill every applicable field:

| Required field | Admission condition |
|---|---|
| Exact subjects | Immutable Koine/dependency/helper revisions, schema/contract versions, lockfiles/features, source archives, source-to-binary recipe, executable digest, Mach-O UUID/load commands/signing identity and loaded images. A tag or path is insufficient. |
| Platform correspondence | Actual hardware/page size, architecture, OS/build/boot identity, SDK/compiler/linker/deployment target, kernel/filesystem/runtime/service versions and corresponding source/configuration. Historical comparison XNU and the mixed SDK observation are not the target basis. |
| Case inventory | Canonical IDs, exact invocation and fixture bytes, expected actual observations, positive/excess/malformed distinctions, applicable aliases and a reason for every inapplicable category. |
| Environment and effects | Complete allowlist with exact values or absence, locale/cwd, encoding negotiation and use, OCR engine and target selection. All children/services, handles and inheritance/closure points. Unknown membership is not zero. |
| Finite costs | Per-case and whole-plan time, input, owned/temporary/native memory, mapped exposure, processes/overlap, descriptors, raw/structured/output bytes, objects/extents/metadata, copies, audits, publication and failure tails. Sum simultaneous maxima before admission. |
| Supervision and loss | Independent continuous-clock/boot source, exact creation/incarnation handles, operation deadline, original containment deadline, blocked-call treatment, holder resolution, stop/reap evidence and retained unknowns. |
| Authority | Explicit scope for the complete named study after review/integration. Existing copy-site approval permits only those controls. Design authority is not execution authority. |

A missing row, source mismatch, unbounded contribution, insufficient retained
capacity or failed positive control prevents the affected group and dependent
groups. There is no adaptive cap, fixture replacement, retry, extra helper or
follow-on useful-fit experiment. A finite timeout limits eligibility and waiting.
It does not prove that a blocked process stopped or that its native work was bounded.

## Real exec floor and bootstrap intervals

Preserve separate `Fi` and `Fe`. `Fi` is the intermediary map at its audited
limit-install site. `Fe` is the **exact real producer** map at the exec setter.
The installable threshold must cover `max(Fi, Fe)` under the corresponding
kernel accounting. Limit readback, RSS, a no-op image or a later map sample
without a relation to the setter cannot supply `Fe`.

The proposed observation route is a conservative reconstruction from one
bounded external sample of the unmodified real producer, plus corresponding
exec/map source. This avoids treating an instrumented producer's different
image as the real subject. It is a method to review, currently unavailable:

1. Pin the producer, intermediary, kernel/build configuration, map category,
   exact setter site and external observation API. Establish that the observed
   metric and the setter use the same map quantity. Retain normalisation and
   rounding. Identify a source-defined sample boundary and synchronisation
   route that needs no additional producer edit or unapproved control seam.
2. Audit **every** possible removal between setter and sample. Derive a finite
   upper bound `R` on their total charged bytes, including loader/unmapping,
   replacement, concurrent threads and observer effects. Additions after the
   setter cannot justify subtracting from the sample. Uncovered routes make
   `R` unknown. Never assume it is zero because the sample is early.
3. Establish a conservative undercount/error correction `E` for the metric,
   sampling and observer perturbation. Account for observer allocation and
   target effects separately, including any effects that can shrink its map.
   If the metric cannot be conservatively related, refuse this route.
4. <!-- tc: depart synonym-rotation because checked arithmetic names overflow detection rather than source verification -->
   In one separately authorised real-producer invocation, take the one bounded
   sample `S` at that boundary. Retain synchronisation/order and original API
   results. Derive `Fe <= S + R + E` with checked arithmetic. This is an
   upper bound, not an assertion that the sample equals the setter floor.
5. Review the complete source derivation and actual subject correspondence
   independently before using the result. Changed kernel, image, observer or
   sampling boundary invalidates that use. The observation itself establishes
   no later map-route enforcement or useful-run fit.

The manifest must name the actual boundary, API, synchronisation, privileges,
`R` derivation and `E` before requesting that invocation. None is filled today.

The provisional count is one real exec and one external observer.
Count all backend/collector/supervisor overlap. It is outside the 13 mechanism
cases and outside the Vision cases below. No observer is silently added to L1.
Its exact work deadline, runtime/stack/native exposures and retained bytes
still need finite values. Therefore no execution request is ready.

If reconstruction cannot bound removals, the alternative is an independently
reviewed observation at the actual kernel setter. That needs a concrete
available instrument, kernel/target correspondence, perturbation bound and
explicit authority. No debugger entitlement, kernel patch, tracing facility or
modified kernel is assumed available or approved. Neither route being possible
leaves `Fe` unavailable. It does not permit substitution of an L3 no-op result.

Retain the existing L1 `Fi` method, observation perturbation and all L2/L3 route
controls. A proposed cap still requires both floors, enforcement and useful
headroom. The intermediary's loader/libSystem bootstrap before installation,
backend and collector bootstrap/runtime/stack/allocator, producer loader after
the setter, inherited members and external framework/device/service work are
separate exposure intervals. Map each interval to an enforceable finite bound
or mark the whole required profile unavailable. Choosing C/libSystem, a process
group or a watchdog does not bound those intervals.

## Native OCR proposal and exact calls

The proposed native slice has four serial producer operations on the pinned
in-process Vision path. It has **three planned Vision recognition calls**, zero
VM launches and zero input actions. Every operation must have an exact fixture,
unit/value, call site and pre-growth assertion before an execution request.
The current authorised Vision-call count remains **zero**.

| ID | Actual boundary and decisive observation | Planned maximum recognition calls |
|---|---|---:|
| V-I-fit | One finite valid crop/PNG. Observe real native-input capacity/copy admission, one real recognition and actual returned objects. Retain input/pixel correspondence. | 1 |
| V-I-excess | Same declared native-input route with a separately frozen first-excess input-unit limit. Refuse before the guarded native allocation/copy and before recognition. No synthetic result. | 0 |
| V-R-fit | One independently frozen finite text fixture and legal result-unit limit. Perform real recognition and collect its actual in-budget result through the guarded result path. | 1 |
| V-R-excess | Frozen finite text fixture and legal first-excess result-unit limit. Perform real recognition once, then refuse before the first prohibited result growth. Retain actual native return and guard observations. | 1 |

Before an execution request, derive each operation's hard maximum capture,
encode and recognition counts from pinned source and exact invocation values.
The contract preserves OCR polling. An elapsed-time test after recognition
does not bound recognition count or a blocked call. The ten-second work ceiling
alone cannot establish the table's maxima.

The proof must cover stop conditions, period, deadline, fallback and every
retry or loop path. A source-correspondent single-cycle production unit is
another candidate only if its source and invocation prove those same maxima.
An unreviewed test shim cannot replace the producer path. If either route
cannot prove maxima of `1,0,1,1`, this slice remains unavailable.
Greater counts or another workload family require k126 reconciliation and a
new producer/review chain before any request. This integration adds neither.

Each operation also needs its own named frame source and immutable source
binding. For a real peer, count its process, role, transport, wire and frame
costs with the producer. For a direct image, prove source correspondence to
the production native-input path. Retain fixture construction, pixel/PNG copies,
allocations and storage costs. Neither route may silently substitute for the
other or use a VM or input action under this proposal.

The dependency must establish that the chosen schema permits each limit and
that the fixture reaches the named boundary. Unexpected/empty OCR or an
unreached guard is inconclusive, not permission to change the image, lower a
limit, repeat Vision or fabricate recognised text. A malformed-unit/header
control belongs in the schema matrix. It calls Vision zero times when rejected
before recognition. Enumerate it there rather than quietly adding a fifth native
operation. Schema units requiring additional post-call malformed/error cases
need a revised explicit call count and review before execution.

Retain the small-fixture ceilings above. For this candidate slice, propose
four ten-second work intervals, each with the existing at-most-twenty-second failure containment.
The absolute whole-study ceiling is 600 seconds, including setup, source/copy audits, collection and final publication. No case or cleanup
gets another containment window. Stop the family at the first unexpected result.
This maximum is `4 * 30 = 120` seconds for cases, leaving at most 480 seconds
for all other work, not an entitlement to extend an operation.

Propose two raw objects per operation, each at most 256 KiB **including** its tail.
The whole retained-evidence ceiling is 8 MiB, including fixtures, copied inputs/binaries, outputs, transcripts, audits and partials. Raw worst case is
2 MiB. Every other maximum must fit the remaining 6 MiB simultaneously.

No VM disk images, archive recursion or temporary uncharged files are allowed in this
slice. If pinned binaries/inputs do not fit, revise and review the proposal
before authority. Do not acquire them under this ceiling first.

These are proposed study ceilings only. Actual `Q`, collector/runtime memory,
native return capacity, service/GPU/Neural Engine/driver work, process and
descriptor overlap and storage metadata are unfilled. The four ordinary roles
supervisor/backend/collector/producer do not bound external services or observers.
No complete finite native cost envelope exists until those returns are filled.
The slice is therefore unavailable, with no permission request made.

## Raw queues, loader diagnostics and R3 observations

The kernel evidence owner must bind installed kernel source/build/configuration to **all** anonymous-pipe routes.
These include both queues simultaneously, ordinary buffers, temporary expansion, direct-transfer/pinned-write paths and accepted bytes held outside the nominal buffer.
Return a conservative total outstanding accepted
byte bound `Q`, temporary/kernel-memory bounds and descriptor/holder rules.
The old comparison header's 64 KiB constant and a stopped-reader pipe-fill
measurement cannot supply this result.

Before any raw row, establish physical retention for `Lout + Lerr + 1 + Q`, metadata and separate setup records.
Include two 4096-byte collector buffers, at most 16 KiB control data and the qualified runtime/stack/allocator contribution.
Include partially persisted buffers. Fit every raw object including its tail.
Raw remains unavailable without `Q`. No finite burst or successful later drain
changes that status.

Specify actual loader diagnostics after descriptor binding as a separate future case, outside R4's four base cases.
Use one pinned, nonproduction copied executable with one declared missing dynamic-library dependency.
Launch it once through the real descriptor path. Pin its load commands and exact missing-name bytes and
prove the failure is in the loader. Bound its possible diagnostic bytes from
corresponding source and capture it under established `Q`/storage limits.

Loader aborts and native crashes may activate host crash-reporting services,
including ReportCrash. They may create reports outside the private evidence
root. Historical service enumeration does not establish the pinned host's
behaviour. Each affected case must identify activation conditions, services,
processes and report paths from corresponding source/configuration.

Bound their time, memory, process/descriptor overlap, report bytes, copies and
filesystem metadata within per-case and whole-study costs. Declare report
contents and privacy effects. Retain reports and partials under the stated
evidence policy, including collection and cleanup costs outside the private
root. Proven suppression on the pinned host is an alternative evidence return.
If neither finite reporting costs nor suppression can be established, the
affected loader/native cases remain unavailable. No host-setting change or
crash execution is authorised here.

Do not assume a short diagnostic or use absent-executable backend refusal as
loader evidence. Missing/unreachable loader subject leaves this case unavailable.
Never change system libraries or a production executable to make it run.

For R3, the approved collector-copy pre-read hold follows descriptor/buffer
binding. One emitter uses two fixed threads, each attempting its one declared
8192-byte stream burst. Include both stacks without inventing another process.

Before admission, return each held stream's maximum accepted capacity from
its initial state across all pinned kernel routes. Keep these per-stream
bounds distinct from total `Q`. If either stream can accept its complete
8192-byte burst, the fixed R3 schedule is infeasible for the blocked-write
obligation. Unknown capacities also prevent admission. A later successful
drain cannot establish the missing blocked-write coverage.

Preserve the two bursts and release rule. A larger burst, another schedule or
another observer family requires k126 reconciliation and a new producer/review
chain. This scope does not change the accepted R count.

Record syscall entry independently. Release the barrier **without waiting for
either blocked write to return**. Then record returns, containment and EOF.
The observation return must supply:

- An independently source-correspondent route that establishes an entered write
  really blocked before release. Entry/return timestamps alone do not prove that.
- An independent prefix-plus-remainder oracle for each writer's accepted bytes.
  A returned write count can establish its completed prefix. For a killed or
  interrupted write without a count, establish an independently qualified accepted
  count at the syscall/kernel boundary, or mark retention coverage unavailable.
  Do not define the oracle as whatever the collector happened to persist.
- Exact source/observer identities, fixed event/storage bounds, perturbation and
  ordering rules. Observer loss must remain distinct from zero accepted bytes.

No such blocking/killed-write instrument is currently selected. R3 is
unavailable pending that concrete observation return and its review. Copy-site
approval alone supplies neither instrument nor execution authority. Preserve R5:
failure before write, or failure after **exactly 1024 real persisted bytes**.

Audit both approved copied sites separately against pinned production source.
Missing, duplicate, unused sites or unrelated differences fail correspondence.
These controls qualify failure handling only, never actual storage failure or Q.

At excess/write failure stop both drains immediately and open the original
containment window once. After all actual writers are proven unable to write,
drain the finite remainder once within that same window/operation deadline.
Unresolved holders, lost collector or failed tail storage retain unknown loss.
Never replace the original lock, add a successor raw writer or call unknown
bytes a clean empty stream.

## Storage, local work and external statuses

The storage evidence owner must return fixed-extent/allocation correspondence,
host copy-on-write and image metadata costs, complete object-pool counts,
protected collection/terminal capacity and original-identity binding. Retain
all attempted slots, parity loss, attachments, partials, duplicates and failed
publication costs. Three 256 MiB images do not reserve arbitrary host metadata
or isolate shared-device failure. Ordinary refusal must preserve protected
writes under the exact accepted backing method.

Require actual write, flush, namespace, readback and later-visibility outcomes
separately, and still-mounted process-loss scans across **all** predecessor slots
and referenced attachments. No power-loss, universal APFS reservation or
cross-volume atomicity claim follows. Qualify precreation and failed-object
paths before relying on recovery. Approved complete-write result substitutions
remain handling controls, not native durability results.

Host work consumes the [caller's complete local-input table](KEEPALIVE-CALLER.md#local-work-and-input-bounds).
The return must cover the following mechanisms in addition to record rows:

| Work owner / scope | Required external evidence |
|---|---|
| Host archive/transfer | Exact archiver/compressor/upload/extract subjects and flags, full source membership/lengths, one planned package and every partial/copy, workspace, read/write counts and finite output. No guessed compression ratio or second packaging pass. |
| Hash and correspondence audit | Every declared input/link/extent and comparison pass, sorting/row/diagnostic bounds, digest implementation and source-copy differences. A streaming buffer bounds neither total reads nor duration. |
| Transcript and sequence output | All original streams plus formatted/duplicated output, buffering, writer/tee holders and failures. Protected output before the `start` operation even when no operation ordinal exists. Final sequence classification and publication under finite limits. |
| Recovery and local audit | Complete immutable slot/object map, parser/decoded/link bounds and aggregate scan work. No empty-slot early stop. Bound the computation at collection indices 15–21 and 24–25, not merely the rows that publish it. |
| Blocked filesystem/process work | Exact supervised API/child route, clock/boot source and original deadline, owned incarnation/descriptor inventory, stop/reap/writer resolution and outcomes for nonreturning read/hash/archive/flush. A wrapper timeout or signal request is not proof of exit or bounded native work. |

Local children run serially only where the implemented plan proves that order.
Count overlap with owner/worker/sleep/backend/collector/producer, archive utilities,
validators and observers. The six-process mechanism ceiling is inapplicable.
Eight named roles can already overlap before additional work. Unknown or
uninterruptible holders block later items, detach and clean completion. They get
no per-item or cleanup containment reset.

Keep inaccessible partials and unknown
loss explicit. Preserve evidence without removing it to regain room.

For every guest probe, the external return must qualify its actual inner tool
status/output meaning before a wrapper encodes a successful domain payload.
Retain outer transport completion, typed response validation, guest exit,
raw stdout/stderr, parse outcome and domain fact as separate observations.
Specify positive, clean-negative and error fixtures for the pinned implementation.

For `spctl --status`, establish the exact enabled and disabled status/output
combinations on the declared OS/tool. Unknown nonzero, malformed output and
transport failure remain unavailable, never inferred disabled. The same rule
covers process/default/inventory/lifecycle probes. Typed not-found or CLI status
3 is unavailable under the acceptance contract. Matching text or a later clean
sample cannot change that outcome. Pin the probe's versioned envelope and schema mapping.

The `start` evidence must cover its actual queue, provision, boot and response stages.
It also needs complete independent inventory, returned subject identity, original boot/clock and holders/side effects from interrupted `start`. Supply finite nonqueue `U_start`.
Retain the separate 600-second queue term. A later VM boot cannot prove the
failed `start` completed, and partial `start` cannot be rerun as a new slot.

## Alternatives, unresolved choices and handoff

The selected approach keeps required claims unavailable until named owners
return source-correspondent evidence. A generic successful native smoke test
would cost fewer records but cannot prove unseen queue, bootstrap or service
bounds. Tightening outer buffers retains those same gaps. Replacing pipes with
a non-growing durable backing could improve process-loss retention only after
its write/seek/aggregate/metadata semantics are qualified. A pre-sized file is
insufficient. No replacement is selected by this leaf.

If hard native/service, queue or blocked-I/O bounds cannot be supplied, present
Antony with the concrete affected guarantee, evidence and costs.
The choice is to fund a named qualified instrument/platform or revise the requirement explicitly. Retaining
the full requirement leaves the dependent profile unavailable. No reduced
outer-buffer-only guarantee, larger cap or empirical-only substitute is adopted.
No new authority is required to write this scope. No incomplete execution
proposal is presented for approval.
