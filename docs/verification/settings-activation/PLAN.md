# Settings activation investigation

K12 diagnostic sample, declared before the first guest. This continues the
unresolved activation outcome; the k4 sample remains separate and unchanged.

Use at most three fresh clones of testanyware-golden-macos-27 at 1920×1080,
named koine-k12-diagnostic-01 through -03. Each executes the existing complete
menu-bar scenario once, against one frozen signed current-source bundle with
observation enabled. Stop the sample after the first classified activation
failure; do not replace interrupted or instrument-invalid attempts. If the cap
does not classify a failure, decompose the remaining investigation.

The sole scenario addition before first launch is a guest preference enabling
JSON-lines observation. No input, focus, wait or activation retry is added.
Synchronous writes and observer registration can affect timing; successful runs
alone cannot qualify the observer as preserving the failure. Require a failure
recorded while observation runs before selecting a repair.

Every row records sequence, process ID, wall clock and monotonic uptime, selection
number, event, native active/key/main-window state and workspace front process.
Record Settings callback entry, show entry, both sides of window show and
activation, menu opening/closure, application and window native notifications.
Notifications may lag WindowServer state; post-failure independent native
snapshots and screenshots supplement them. No absence claim follows from a
missing or truncated trace. Default operation leaves observation disabled.

Before each run, freeze all scenario helper inputs, wrapper, observer and full
bundle inventory; check their hashes afterwards. Save source copies and golden
config/disk/NVRAM hashes. After a failed scenario, capture native activation and
CoreGraphics order, agent windows and screenshot before any key, focus, repeated
menu action or launch. Download the trace, preserve the scenario and Task exits
separately, all new artifacts, environment and installed endpoint inventories.
Stop the guest on every outcome. Classify unexecuted assertions as NOT RUN.

A repair requires causal evidence and its own predeclared bounded complete
fresh-guest sample. Diagnostic passes are not repair acceptance or a reliability
estimate. No release or upstream report is authorized.
